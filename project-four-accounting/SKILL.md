# 项目四算管理

## R — 原文 (Reading)

> 项目概算、预算、核算、决算是项目经营管理中的关键活动，概算是设计项目利润的过程，预算和核算是管理增收节支的过程，决算是传承经验的过程。项目四算拉通的服务对象是系统部以及各类项目组，价值在于支撑项目层面的经营管理。
>
> — 任正非, 华为管理手册（财务四算）, 第6章

> 项目是细胞，细胞最重要。没有项目核算，系统部和代表处的经营管理都无法有效地开展。项目和客户的账算清楚了，华为整个系统的部门账就算清楚了。
>
> — 华为管理手册（财务四算）, 第3章

> 华为要把项目的计划、预算、核算的权利，销售的决策权利授予一线，让听得见炮声的人来做决策。但打不打仗是由后方决定的，怎么打仗前方说了算。
>
> — 华为管理手册（财务四算）, 第3章

## I — 方法论骨架 (Interpretation)

项目四算是华为将财务管理下沉到最小经营单元（项目）的核心工具。它把项目从"成本中心"转变为"利润中心"。

**四算定义与分工：**

1. **概算（Estimate）——设计利润**
   - 发生在签约前，估算合同收入、成本、费用、利润
   - 由项目一把手（代表/系统部主任）担任概算经理
   - 输出：项目报价基准线、成本基准线、利润目标
   - 关键原则：概算是合同谈判的基础，也是项目交付的预算输入

2. **预算（Budget）——授权作战**
   - 承接概算利润目标，落实经营责任人并充分授权
   - 项目经理拥有预算权、资源调配权、考核权
   - 输出：项目年度/全周期预算、资源计划
   - 关键原则：预算就是指挥中心，拥有组织作战的权利

3. **核算（Accounting）——过程监控**
   - 对照预算目标进行过程监控，及时预警偏差
   - 项目财务（PFC/BFC）是第一责任人
   - 输出：月度/季度经营报告、偏差分析、风险预警
   - 关键原则：用核算监控授权，指挥权才能真正下沉

4. **决算（Settlement）——经验传承**
   - 项目执行完成后的全面复盘
   - 刷新能力基线，提升下一次概算能力
   - 输出：项目决算报告、经验总结、基线更新
   - 关键原则：决算是经验传承的过程，不是"秋后算账"

**项目铁三角 + CFO 的责权设计：**
- 项目CEO（需求/交付/方案经理铁三角）+ 项目CFO
- 项目CEO对经营结果负责，项目CFO对预算/预测/核算准确性负责
- 项目CFO参与项目全周期关键经营活动

## A1 — 书中的应用 (Past Application)

### 案例 1: 华为交付项目成本节约分享机制
- **问题**: 如何让交付团队主动降低成本、提升效率？
- **方法论的使用**: 建立项目成本基线（如100万），项目经理通过提升效率实际花费90万完成交付。节省的10万中拿出部分分享给交付团队，财务上记为成本，同时刷新能力基线
- **结论**: 用"节约分享"机制将项目利润与团队激励直接挂钩
- **结果**: 激发了交付体系持续提升效率、降低成本的能动性

### 案例 2: 华为区域利润中心建设
- **问题**: 代表处经营管理重心不清，责权不对等
- **方法论的使用**: 以项目为核算单元，建立"项目→系统部→代表处"三级利润累积机制；项目经理拥有人员考核权、人事权、财权；优秀前30%项目团队接管落后后30%团队
- **结论**: 划小核算单位，责权对等，激活一线
- **结果**: 区域经营效率显著提升，干部从项目实战中选拔

### 案例 3: 华为IFS项目四算与LTC强协同
- **问题**: 财务流程与销售交付流程脱节
- **方法论的使用**: 将项目四算嵌入LTC（线索到回款）主流程，IFS输出四算方案，CRM在LTC管理体系中明确四算定位并集成关联点
- **结论**: 四算不是独立的财务流程，而是主业务流程的财务支撑
- **结果**: 实现了财务活动与业务活动的端到端拉通

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司想做项目制改革，需要把项目从成本中心变为利润中心时
2. 项目经理抱怨"有责无权"，需要设计责权对等机制时
3. 项目总是亏损或利润不清，需要建立项目核算体系时
4. 要培养项目CFO或项目财务经理队伍时
5. 项目报价与交付脱节，需要拉通签约前到交付后的财务闭环时

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断项目制成熟度**
   - 完成标准: 识别用户当前是否以项目为核算单元、项目经理有哪些权/缺哪些权、项目财务数据是否清晰

2. **设计项目四算流程**
   - 完成标准: 明确概算→预算→核算→决算在每个阶段的责任人、输入输出、关键动作
   - 概算阶段: 由经营主体一把手负责，输出成本基准线和报价策略
   - 预算阶段: 由项目经理负责，输出资源计划和授权方案
   - 核算阶段: 由项目财务负责，输出偏差分析和风险预警
   - 决算阶段: 由项目团队负责，输出经验总结和基线刷新

3. **建立项目责权对等机制**
   - 完成标准: 明确项目经理在人事权、考核权、财权、资源调配权上的具体授权范围

4. **设计项目激励方案**
   - 完成标准: 建立基于项目经营结果的考核与分享机制（如成本节约分享、准时交付奖励、利润改善奖励）

5. **拉通四算与主业务流程**
   - 完成标准: 明确四算在销售流程（LTC）或研发流程（IPD）中的嵌入点和协同机制

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯职能部门的费用报销管理 — 用常规财务制度即可
- 无项目制运作的传统销售模式 — 先推动项目制改革
- 只做一个项目的预算表 — 用财务工具即可
- 项目规模极小（<5人）且周期极短（<1月）— 四算过重

### 作者在书中警告的失败模式

- **概算变成"拍脑袋"**: 概算没有基于历史基线和成本模型，导致报价失真、交付亏损
- **核算沦为"死后验尸"**: 核算只在项目结束后做，过程中没有预警和纠偏
- **项目经理有权无责或有责无权**: 授权不配套考核，或要求负责但不给预算权

### 作者的盲点 / 时代局限

- 华为项目四算基于大型ICT项目（周期长、金额大、定制化高），对于敏捷开发、SaaS订阅等轻量级项目需要简化
- 文档中强调"铁三角"，但在知识密集型项目（如咨询、设计）中可能需要调整为其他组织形态

### 容易混淆的邻近方法论

- 与IPD（集成产品开发）: IPD是研发流程，项目四算是财务支撑工具；IPD中也有财务活动，但聚焦产品投资回报
- 与LTC（线索到回款）: LTC是销售交付流程，项目四算是LTC中的财经管理子流程
