# main-channel-guardian

- **Domain**: 战略聚焦 / 边界管理 / 多元化vs专业化

- **Revision**: 1.0

## When to Activate

当用户面临以下场景时激活：
- 讨论"我们该不该做XX新业务"时判断是否在主航道内
- 面临多元化诱惑，需要评估是否偏离核心业务
- 设计"聚焦vs扩展"的战略边界
- 讨论"平台/生态的边界在哪"（如不碰数据、不碰应用）
- 评估创新项目是否"边界外瞎搞"

不适用于：已有明确战略方向的执行问题、纯粹的市场机会分析（无边界考量）、个人职业规划。

## Core Methodology

### 主航道定义法（Main Channel Definition）

华为对主航道的定义不是静态的"业务列表"，而是动态的能力延伸逻辑：

> "智慧要在主航道边界里面，不做边界外的事情。人工智能要与主航道业务捆绑，在边界之内可以大投，一起扩展更多的灵感更多的发挥。离开了这个边界，偏离主航道的就不给钱了。" ——任正非

#### 主航道三维检验（3-Dimension Main Channel Test）

**维度1：能力延伸轴**（Can we leverage existing capabilities?）
- 新业务是否基于现有核心技术能力的自然延伸？
- 华为案例：从通信设备→手机（同属通信技术）→芯片（同属半导体）→云（同属ICT基础设施）= 能力延伸
- 反例：华为不做房地产、不做小商品 = 能力无关

**维度2：客户价值轴**（Does it serve existing customer needs?）
- 新业务是否服务于现有客户群的新需求？
- 华为案例：运营商客户需要云化转型→华为云 = 客户价值延伸
- 反例：华为不做公共AI产品面向社会消费者 = 现有客户（企业/运营商）不需要

**维度3：竞争壁垒轴**（Does it reinforce competitive moat?）
- 新业务是否强化而非稀释现有竞争优势？
- 华为案例：自研芯片→强化手机差异化竞争力 = 强化壁垒
- 反例：如果做通用AI小商品→与Google/百度直接竞争，稀释聚焦优势 = 稀释壁垒

**通过标准**：至少满足2个维度，且不满足任何维度的反例条件。

### "不做边界外的事情"操作清单

任正非对华为AI业务提出的六条边界规则（可直接迁移）：

1. **自己的狗食自己先吃**：新技术先用于改善自身业务，不对外卖通用产品
2. **在主航道里面大投**：边界内可以大胆投入，边界外一分钱不给
3. **不要什么砖都自己造**：利用产业分工，在别人有优势的地方用别人的
4. **像东北乱炖，跨学科人才引进**：边界内允许跨学科思维碰撞
5. **河水一泛滥后就在马路上抓鱼**：泡沫破灭时是人才抄底时机（但只招主航道相关的）
6. **不要树敌过多，要多交朋友**：边界内合作，边界外不竞争

### 华为云"三不原则"：平台边界的标杆

华为云作为平台型业务的边界管理范例：
- **上不做应用**：不做SaaS应用，让合作伙伴做
- **下不碰数据**：不碰客户数据，只做基础设施
- **不做股权投资**：不通过投资控制生态伙伴

**底层逻辑**：平台的核心价值是"使能"而非"掠夺"。如果平台方既做裁判又做运动员，生态伙伴会失去信任。

### 边界动态调整机制

主航道边界不是一成不变的：
- **2002年前**：华为主航道=电信设备（不做手机是死命令）
- **2002年后**：手机成为主航道（发现不做手机是战略失误，立即修正）
- **2011年后**：企业业务/云计算进入主航道
- **2019年后**：智能汽车解决方案进入主航道（但不造车）

**调整触发条件**：
1. 战略误判被证实（如任正非承认不做手机是错误）
2. 产业代际切换（如4G→5G→AI时代）
3. 客户需求根本性变化（如运营商从买设备到买云服务）

## Usage Flow

1. 用户提出新业务想法 → 跑三维检验
2. 用户讨论投资优先级 → 应用"边界内大投，边界外不给钱"
3. 用户设计平台/生态策略 → 应用"三不原则"
4. 用户质疑现有边界是否过窄 → 评估动态调整必要性

## Example

**Input**: "我们是一家做工业物联网平台的公司，现在团队想做一个面向消费者的智能家居App，老板很犹豫，该不该做？"

**Skill Response**:
> **维度1 能力延伸**：工业IoT平台→消费者智能家居App = 技术栈部分重叠（IoT连接、设备管理），但用户交互、商业模式完全不同。**部分满足**。
>
> **维度2 客户价值**：工业客户（工厂/设备商）vs 消费者 = 完全不同的客户群。**不满足**。
>
> **维度3 竞争壁垒**：做消费者App需要与小米/华为/苹果竞争，会分散工业平台的研发投入。**反例满足**（稀释壁垒）。
>
> **结论**：不满足2个维度，且满足反例条件。**建议不做**。
>
> **替代方案（边界内延伸）**：
> - 如果客户（工业企业）有"智慧园区/智慧办公"需求→做B2B2C的园区智能管理 = 客户价值延伸
> - 如果技术团队有智能家居热情→输出IoT连接模块给家电厂商 = 能力延伸，不直接做C端
>
> **如果一定要做**：建议独立团队、独立预算、独立考核，且不占用工业平台研发资源。但任正非对这种"边界外项目"的态度是："不做。"

## Anti-Patterns
- ❌ "只要赚钱就做" — 没有边界的企业最终会资源分散、竞争力瓦解
- ❌ "竞争对手做了我们也得做" — 跟风跨界是边界失守的典型症状
- ❌ "边界=永不改变" — 华为也曾把"不做手机"作为死命令，后来修正了
- ❌ "平台方什么都做" — 既做基础设施又做应用，会吓跑生态伙伴
