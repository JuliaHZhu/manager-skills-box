# five-force-talent-developer — 华为研发人员培养"五力模型"

## R (Reading) — 原文引用

> "华为研发人员培养的'五力模型'：学习力、激励力、发展力、资格力、胜任力。"（Ch16）

> "研发组织能力目标确定 → 研发培训课程体系设计 → 研发人员的培训管理 → 研发人员的思想导师制 → 研发平台。"（Ch16.1）

> "激励策略分四个阶段：实习期、过渡期、发展期、稳定期。"（Ch16.2）

> "双重资格晋升制度确保个人职业发展通道畅通：管理通道和技术通道并行。"（Ch16.3.2）

> "任职资格体系是华为研发管理的基石，它将员工能力显性化、标准化、可衡量。"（Ch16.4）

> "胜任力是岗位匹配度，不仅看能力是否达标，还要看是否适合岗位特性。"（Ch16.5）

## I (Interpretation) — 方法论骨架

华为研发人才培养不是"开几门课"那么简单，而是一个**系统工程**：先通过任职资格定义"什么是合格"，再通过培训体系确保"能达到合格"，通过双通道晋升让"合格者有出路"，通过分阶段激励让"每个人有动力"，最终通过胜任力评估确保"人岗匹配"。

**五力模型逻辑链：**

```
学习力（能学） → 激励力（愿学） → 发展力（有出路） → 资格力（有标准） → 胜任力（能胜任）
```

**关键洞察：** 五个力缺一不可。有学习力没激励力=白学；有激励力没发展力=学完就跑；有发展力没资格力=晋升靠关系；有资格力没胜任力=纸上谈兵。

## A1 (Past Application) — 书中案例

**华为新员工培养体系：**
- **实习期（0-6月）**：思想导师一对一辅导，重点是文化融入和基础技能
- **过渡期（6-12月）**：独立承担模块任务，导师逐步放手
- **发展期（1-3年）**：参与完整项目，开始向专家或管理者方向分化
- **稳定期（3年+）**：成为导师，输出知识，参与战略级项目

**华为任职资格体系：**
- 技术通道：工程师 → 高级工程师 → 专家 → 资深专家 → 首席专家
- 管理通道：工程师 → 项目经理 → 部门经理 → 产品线总监 → 研发VP
- 每个级别有明确的能力标准、经验要求、绩效门槛
- 晋升必须"先认证、后上岗"

**思想导师制：**
- 每位新员工配备一位资深员工作为思想导师（非直接主管）
- 导师负责：文化传导、技能辅导、心理支持、职业规划
- 导师有考核指标：徒弟转正率、徒弟首年绩效

## A2 (Future Trigger) — 何时调用

- 研发团队青黄不接，老员工离职后无人能接班
- 新员工入职半年还无法独立工作，融入慢
- 技术人员职业发展只有"做管理"一条路，导致技术骨干流失
- 培训做了很多但效果不佳，员工觉得"学了没用"
- 晋升靠领导印象而非能力标准，引发内部不满
- 招聘时发现"面试时很厉害，入职后干不好"
- 团队士气低落，缺乏成长动力

## E (Execution) — 可执行步骤

### Step 1: 建立任职资格体系（资格力）

**定义各层级标准：**

| 层级 | 能力要求 | 经验要求 | 绩效要求 |
|------|---------|---------|---------|
| **初级工程师** | 掌握1-2门编程语言/工具，能独立完成模块 | 0-2年 | 按时完成任务 |
| **中级工程师** | 掌握系统设计，能独立负责子系统 | 2-5年 | 质量达标 |
| **高级工程师** | 架构设计能力，能指导他人 | 5-8年 | 有创新贡献 |
| **专家** | 领域权威，能解决复杂技术难题 | 8-12年 | 专利/论文/技术突破 |
| **资深专家** | 行业影响力，能定义技术方向 | 12年+ | 战略级贡献 |

**认证流程：**
1. 员工申请 → 准备证据（代码、文档、项目经历）
2. 评审委员会评审（同级+上级+HR）
3. 答辩/实操考核
4. 认证结果 + 差距分析
5. 制定提升计划

### Step 2: 设计培训体系（学习力）

**三层培训架构：**

| 层级 | 对象 | 内容 | 方式 |
|------|------|------|------|
| **公司级** | 全员 | 文化、流程、通用技能 | 课堂/线上 |
| **部门级** | 研发团队 | 专业技术、工具、平台 | 工作坊/实战 |
| **个人级** | 个体 | 针对性技能补缺 | 导师制/自学 |

**新员工培养路径（180天）：**
- 第1周：文化培训 + 环境熟悉
- 第2-4周：基础技能培训 + 导师结对
- 第2-3月：参与实际项目（辅助角色）
- 第4-6月：独立承担模块任务
- 第6月：转正答辩

### Step 3: 实施思想导师制

**导师选拔标准：**
- 技术能力中上（前30%）
- 沟通意愿强，有耐心
- 在公司工作满2年
- 上一财年绩效B+

**导师职责清单：**
- 每周至少1次1:1沟通
- 每月提交徒弟进展报告
- 协助制定学习计划
- 解答技术和文化问题

**导师激励：**
- 导师津贴
- 徒弟转正后一次性奖励
- 徒弟绩效优秀，导师获得额外奖金
- 导师经历作为晋升加分项

### Step 4: 设计分阶段激励（激励力）

| 阶段 | 核心需求 | 激励重点 |
|------|---------|---------|
| **实习期（0-6月）** | 安全感、融入感 | 及时认可、导师关怀、清晰的转正标准 |
| **过渡期（6-12月）** | 成就感、能力认可 | 挑战性任务、绩效反馈、技能培训 |
| **发展期（1-3年）** | 成长空间、职业发展 | 晋升机会、双通道选择、项目历练 |
| **稳定期（3年+）** | 影响力、自我实现 | 专家头衔、导师角色、战略参与、股权激励 |

### Step 5: 建立双通道晋升（发展力）

**技术通道：**
工程师 → 高级工程师 → 专家 → 资深专家 → 首席专家 → Fellow

**管理通道：**
工程师 → 技术组长 → 项目经理 → 部门经理 → 产品线总监 → 研发VP

**关键设计：**
- 两条通道级别对等、待遇对等
- 允许双向转换（专家可转管理，管理者也可转专家）
- 转通道需重新认证
- 技术通道的天花板不低于管理通道

### Step 6: 胜任力评估（胜任力）

**评估维度：**
1. **知识**：专业知识掌握程度
2. **技能**：实际操作能力
3. **经验**：项目经历和成果
4. **特质**：性格、价值观与岗位匹配度

**评估方式：**
- 360度评估（上级、同事、下属、客户）
- 绩效数据分析
- 关键事件访谈
- 心理测评（可选）

**应用：**
- 招聘时：判断候选人是否适合岗位
- 晋升时：判断是否达到下一级标准
- 调岗时：判断人岗匹配度
- 培养时：识别能力差距

## B (Behavior) — 行为变化

**Before:** 人才培养靠"师傅带徒弟"的口口相传，没有标准、没有体系、没有出路。技术好的走管理，管理的做不好又回不去，人才断层反复出现。

**After:** 每个层级有明确标准，每个人有清晰路径，学习有体系支撑，晋升有客观依据，技术专家和管理者同样受尊重。
