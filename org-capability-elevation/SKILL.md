# 组织能力升维

## R — 原文 (Reading)

> 企业经营是一项复杂的系统工程，必须从业务管理、职能管理、要素管理、协作管理、战略管理五个方面，系统构建组织能力。
>
> — 华为战略管理实践, 第10章

> 如果组织队伍不足够强大，战略难以落地实施。中国企业战略落地的实施过程中，很困难的就是组织能力，特别是在转型的时期。组织能力的构建也恰恰是华为的一个强项，战略解码的过程就是对组织能力提要求的过程，也是打造组织能力的过程。
>
> — 华为战略管理实践, 第18章

---

## I — 方法论骨架 (Interpretation)

组织能力不是"招更多的人"或"开更多的会"，而是**管理复杂度的系统性提升**。华为将组织管理能力分为五个层级，企业需要在不同发展阶段逐步升维：

| 层级 | 核心问题 | 典型特征 | 适用阶段 |
|-----|---------|---------|---------|
| **业务管理** | 如何把具体业务做成？ | 依赖个人经验、英雄主义、随机应变 | 初创期（<50人） |
| **职能管理** | 如何让专业职能运转起来？ | 建立HR、财务、销售等专业职能，分工明确 | 成长期（50-200人） |
| **要素管理** | 如何管理关键要素（人/财/物/信息）？ | 流程化、标准化、数据化 | 扩张期（200-1000人） |
| **协作管理** | 如何让多部门高效协同？ | 端到端流程、跨部门协作机制、矩阵组织 | 成熟期（1000+人） |
| **战略管理** | 如何让组织持续走在正确方向上？ | DSTE流程、战略解码、变革管理、自我批判 | 大规模期 |

**核心观点：**
1. 每个层级的管理能力不是替代关系，而是**包含关系**——能做战略管理的前提是业务、职能、要素、协作管理都已扎实
2. 业务转型（如从卖产品到卖解决方案）失败，往往不是因为战略错，而是因为**组织能力没有同步升维**
3. 战略解码的过程本身就是对组织能力提要求、打造组织能力的过程

## A1 — 书中的应用 (Past Application)

### 案例 1: 华为从To B到To C的组织能力重构
- **问题**: 华为长期做运营商业务（To B），终端业务（To C）初期完全依赖To B思维，品牌低端、渠道混乱
- **方法论的使用**: 认识到To C需要完全不同的组织能力——客户选择（从运营商到消费者）、价值主张（从功能到体验）、渠道（从直销到零售）、品牌（从隐形到显性）。组织能力建设包括：建立消费者BG、引入外部人才、重构供应链、建立品牌和市场营销能力
- **结论**: 业务转型必须伴随组织能力升维，否则战略就是空谈
- **结果**: 终端业务成功，华为手机全球领先

### 案例 2: 华为战略管理部的7大职能（组织能力建设案例）
- **问题**: 华为400多个业务单元如何实现连续10年以上100%完成战略目标？
- **方法论的使用**: 华为建立战略管理部，系统承载7大职能：SP制定与监控、市场洞察（3个数据库）、战略专题管理、产业生态建设、投资组合与绩效政策、战略指引、战略安全。这是"战略管理"层级的组织能力具象化
- **结论**: 战略管理不是CEO一个人的事，需要专门的组织能力建设
- **结果**: 华为战略目标实现率极高

### 案例 3: 中国企业从卖元器件到卖解决方案的转型失败（反面教材）
- **问题**: 很多企业想从卖标准产品转型为卖定制化解决方案，但屡战屡败
- **方法论的使用**: 分析发现失败根因不是产品不行，而是组织能力不匹配——销售团队还是"卖盒子"思维、交付团队没有解决方案实施能力、财务模型还是产品毛利思维、组织结构还是产品线制而非客户制
- **结论**: 业务转型需要组织能力从"业务管理"或"职能管理"升维到"协作管理"甚至"战略管理"
- **结果**: 转型失败的企业往往退回原业务，错失机会

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 团队从20人扩张到100人，发现"以前那套不管用了"时
2. 业务从单一产品扩展到多产品线，管理复杂度激增时
3. 从卖产品转型卖解决方案，发现组织能力跟不上时
4. 公司并购后整合困难，两个组织的管理方式冲突时
5. 战略很明确但总是落不了地，怀疑"人不行"时（往往其实是组织能力没升维）

### 语言信号 (用户的话里出现这些就应激活)

- "人一多就管不过来了"
- "以前很灵活，现在很僵化"
- "业务转型但团队跟不上"
- "组织能力 / 管理升级 / 组织转型"
- "战斗力下降 / 部门墙 / 协同困难"
- "org capability / management elevation / organizational transformation / scaling challenges"

### 与相邻 skill 的区分

- 与 `stretch-goals-capability-building` 的区别: 本 skill 聚焦于组织管理能力的系统性升维，高目标 skill 聚焦于用目标倒逼能力的杠杆机制
- 与 `strategy-decoding-sp-bp` 的区别: 战略解码对组织能力"提要求"，本 skill 回答"如何建设这些能力"
- 与 `dste-strategy-execution` 的区别: DSTE是流程框架，本 skill 是组织能力建设的层级模型

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断当前管理层级**
   - 完成标准: 通过5-7个问题判断用户当前组织处于哪个管理层级，以及面临的典型瓶颈
   - 诊断问题示例:
     - 是否已建立专业职能部门（HR/财务/销售）？
     - 关键业务流程是否已标准化？
     - 跨部门协作是否依赖个人关系而非流程机制？
     - 是否有专职的战略管理或变革管理职能？

2. **识别能力缺口**
   - 完成标准: 列出当前层级与目标层级之间的3-5个关键能力缺口

3. **设计升维路径**
   - 完成标准: 提供从当前层级到下一层级的具体建设动作（流程、组织、人才、IT系统）
   - 原则: 一次只升一级，不要跳级；每一级的基础打牢再往上走

4. **制定实施计划**
   - 完成标准: 产出6-12个月的组织能力建设计划，包含关键里程碑和验收标准

5. **预警常见陷阱**
   - 完成标准: 列出2-3个该层级升级时的常见失败模式，并给出规避建议

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯个人执行力问题（如某个员工总是拖延）— 用个人绩效管理
- 团队人数极少（<10人）尚无管理复杂度 — 小团队不需要复杂组织能力建设，保持灵活更重要
- 通过简单加人就能解决的问题 — 这是资源问题，不是组织能力问题
- 企业文化已彻底崩坏时的修复 — 需要先进行文化重建，再谈管理能力升维

### 作者在书中警告的失败模式

- **跳级建设**: 业务管理还没做好就搞战略管理，结果是空中楼阁
- **复制华为全套**: 华为的管理体系是20年演进的结果，中小企业照搬会窒息
- **忽视业务管理基础**: 组织能力建设的根基是一线业务管理的能力，脱离业务谈管理是官僚主义

### 作者的盲点 / 时代局限

- 华为的五层级模型偏传统科层制组织，对扁平化组织、敏捷团队、远程协作等新型组织形态的适配性需调整
- 强调"战略管理部"等专职职能，但在DAO、合弄制等去中心化组织中可能不适用

### 容易混淆的邻近方法论

- 与组织发展（OD）: OD是广义的组织变革学科，本 skill 聚焦于管理能力层级的系统性诊断和建设
- 与变革管理: 变革管理是"如何推动变化"，本 skill 是"应该变化到什么状态"
