# red-team-analyst — 红队策略分析方法论

## R (Reading) — 原文引用

> "红队策略是指人为地在组织或公司中成立一支‘敌军’，以模拟攻击、压力测试的方式，去找出战略和计划中的漏洞。"（Ch5.4）

> "7大批判分析办法：批判性思考法、论证剖析法、关键假设检查法、概率分析法、珠链分析法、利益相关者分析法、竞争假设分析法。"（Ch5.4）

> "7大想象力方法：四视角审视法、由外及内思考法、未来可能性分析法、事前检验分析法、对手行为预测法、SWOT分析法、丰田5WHY分析法。"（Ch5.4）

> "3大逆向分析法：灾难性事件假设分析法、内部分组辩论分析法、魔鬼的辩护。"（Ch5.4）

> "魔鬼的辩护的核心在于，对所提出战略至关重要的信念或主张，证明最不可能发生的事情也会发生。"（Ch5.4）

## I (Interpretation) — 方法论骨架

红队策略是一套**结构化的逆向思维工具箱**，用于在决策者被"确认偏误"绑架之前，强制性地暴露计划中的脆弱假设和盲点。

**三层工具箱**：

### 第一层：批判分析（7种）—— "这个计划哪里错了？"

| 方法 | 核心问题 | 适用场景 |
|------|---------|---------|
| **批判性思考法** | 信息的来源可靠吗？推理过程有漏洞吗？ | 任何计划的基础逻辑审查 |
| **论证剖析法** | 结论是如何从前提推导出来的？每一步都成立吗？ | 复杂战略的逻辑链条检验 |
| **关键假设检查法** | 计划成功必须满足哪些假设？这些假设成立吗？ | 新项目/新市场进入 |
| **概率分析法** | 各情景发生的概率是多少？期望值计算合理吗？ | 投资决策、风险量化 |
| **珠链分析法** | 各环节之间的依赖关系是什么？哪一环最脆弱？ | 供应链、项目计划 |
| **利益相关者分析法** | 各方会怎么反应？他们的激励相容吗？ | 并购、联盟、政策变化 |
| **竞争假设分析法** | 还有没有其他解释/方案同样合理？ | 情报分析、诊断问题 |

### 第二层：想象力方法（7种）—— "还有什么可能？"

| 方法 | 核心问题 | 适用场景 |
|------|---------|---------|
| **四视角审视法** | 客户/竞争对手/合作伙伴/旁观者会怎么看？ | 产品定位、品牌策略 |
| **由外及内思考法** | 如果我是竞争对手，我会怎么打？ | 竞争战略 |
| **未来可能性分析法** | 3-5年后行业可能变成什么样？ | 长期战略规划 |
| **事前检验分析法** | 假设这个项目已经失败了，最可能的原因是什么？ | 重大项目启动前 |
| **对手行为预测法** | 竞争对手对我们的行动最可能的3种反应是什么？ | 市场进入、价格战 |
| **SWOT分析法** | 我们的优势/劣势/机会/威胁是什么？ | 通用战略分析 |
| **丰田5WHY分析法** | 问题的根本原因是什么？追问5层。 | 问题诊断、质量改进 |

### 第三层：逆向分析（3种）—— "反过来会怎样？"

| 方法 | 核心问题 | 适用场景 |
|------|---------|---------|
| **灾难性事件假设分析** | 如果最坏的情况发生，我们有预案吗？ | 危机管理、业务连续性 |
| **内部分组辩论分析** | 让内部团队分正反两方辩论，强制暴露盲点 | 重大决策前 |
| **魔鬼的辩护** | 努力为最不可能发生的事情寻找证据 | 打破乐观偏误 |

## A1 (Past Application) — 书中案例

**"跑鞋计划"示例（书中教学案例）**：
- 第一步：用关键假设检查法——列举计划成功的所有假设（市场需求不变、消费者希望看到新产品、公司有生产能力……）
- 第二步：用对手行为预测法——预测竞争对手可能的反击（降价、推出同品类）
- 第三步：用魔鬼的辩护——证明"跑步这项运动仍然像以往一样受欢迎"，探究销量不好的真正原因

**亚马逊的魔鬼辩护人**：
- 亚马逊内部设置"魔鬼辩护人"角色
- 如果数据有漏洞，他们会追问"为什么你们没能拿到数据？"
- 预测CEO可能会问的所有问题，提前反复检查

**eBay创始人皮埃尔·奥米迪亚**：
- "我的学习过程一直是不同意别人对我说的话，我会采取相反的立场，强迫别人为他们自己辩护。"

## A2 (Future Trigger) — 何时调用

- 商业计划书完成后、融资路演前——"这个计划有没有盲区？"
- 重大投资决策前——"如果投错了，最可能的原因是什么？"
- 新产品发布前——"竞争对手会怎么反击？"
- 年度战略规划——"我们过去的假设有哪些已经过时了？"
- 感觉"这个方案太完美了"——完美往往是盲点的信号

## E (Execution) — 可执行步骤

### Step 1: 选择分析深度

| 深度 | 时间 | 工具数量 | 适用场景 |
|------|------|---------|---------|
| **快速扫描** | 30分钟 | 1-2种 | 日常决策、时间紧迫 |
| **标准审查** | 半天 | 3-5种 | 重要项目、年度规划 |
| **深度压力测试** | 1-2周 | 全部17种 | 并购、进入新市场、大额投资 |

### Step 2: 执行关键假设检查法（最常用）

**操作流程**：
1. 列出计划成功必须满足的所有假设（至少10条）
2. 对每条假设追问：
   - 这条假设基于事实还是偏见？
   - 假设成立还需要什么条件？
   - 如果假设在任何情况下都成立吗？
   - 假设不成立时，计划怎么改？
3. 标记"弱势假设"——对计划结果威胁最大的假设
4. 对弱势假设：要么证实它，要么准备应急计划

**示例模板**：
```
假设1: ___________
基于事实/偏见？ ___________
证伪条件： ___________
若证伪，应急计划： ___________
风险等级：高/中/低
```

### Step 3: 执行魔鬼的辩护（最强武器）

**操作流程**：
1. 选择计划中最核心的信念/主张
2. 强迫自己证明"最不可能的事情也会发生"
3. 用同样的数据构建一个与原解释相矛盾的论点
4. 努力找出支持逆向论证的新证据
5. 与团队同步，逐一验证

**示例**：
- 核心信念："我们的跑鞋卖不好是因为人们跑步变少了"
- 魔鬼辩护："跑步运动仍然像以往一样受欢迎，销量不好的真正原因是____"

### Step 4: 执行事前检验分析法（Pre-mortem）

**操作流程**：
1. 假设项目已经失败（设定在未来某个时间点）
2. 团队成员独立写下"失败的最可能原因"
3. 汇总所有原因，按频率排序
4. 对排名前3的原因制定预防措施

### Step 5: 整合输出

**红队分析报告模板**：
```
分析对象：_________
分析日期：_________
参与人员：_________

一、关键假设检验
  最危险的3个假设：_________
  应急计划：_________

二、竞争对手预判
  最可能的3种反击：_________
  我们的应对：_________

三、魔鬼辩护发现
  被忽视的风险：_________

四、事前检验结论
  项目最可能的失败原因：_________
  预防措施：_________

五、最终建议
  执行/修改/搁置/否决
```

## B (Boundary) — 何时不适用

1. **纯数据建模**：财务预测、工程计算等已有明确方法论的领域
2. **合规检查**：法律、安全等"是/否"问题，不需要红队分析
3. **创意发散阶段**：brainstorming需要先鼓励疯狂想法，批判过早会扼杀创意
4. **执行中的微决策**：日常运营中的快速判断，不需要系统性逆向分析
5. **高度不确定的 exploratory 项目**："连假设是什么都不知道"时，红队分析无从下手
