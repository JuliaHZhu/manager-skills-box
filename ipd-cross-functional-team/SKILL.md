# IPD 跨部门团队与决策评审方法论

基于华为IPD体系，产品创新是**全公司的行为**，不是研发部门的独角戏。通过跨部门团队（IPMT/PDT）和决策评审（DCP）机制，实现从机会到商业变现的端到端负责。

## 核心原则

- **跨部门协同是IPD的灵魂**：创新需要市场、研发、制造、采购、财务、服务等各领域智慧
- **职能部门退到幕后**：为跨部门团队提供资源和专业能力支撑
- **端到端负责**：团队对产品的商业成功负责，不是只对某个环节负责
- **投资决策视角**：评审不是技术评审，是业务评审——"值不值得继续投"

## 两类核心团队

### IPMT（集成产品管理团队）——决策层
- **组成**：公司决策层人员（产品线总裁、研发总裁、市场总裁等）
- **职责**：
  - 确保公司在市场上有正确的产品定位
  - 保证资源、控制投资
  - 管理多个PDT，从市场角度考察盈利性
  - 适时终止前景不好的项目
  - 将有限资源投到高回报项目
- **运作方式**：定期会议，对每个PDT进行DCP决策评审

### PDT（产品开发团队）——执行层
- **组成**：项目经理（LPDT）+ 各功能领域代表（研发、市场、制造、采购、财务、质量、服务等）
- **职责**：
  - 制定具体产品策略和业务计划
  - 按计划执行并保证及时完成
  - 确保产品按计划投放市场
  - 对产品商业成功负责
- **性质**：虚拟组织，成员在开发期间全职或大部分时间投入

## PDT核心角色

| 角色 | 核心职责 |
|------|----------|
| LPDT（项目经理） | 团队 leader，对项目整体负责，必须有市场经验 |
| 研发代表 | 技术方案、开发进度、质量 |
| 市场代表 | 市场需求、竞争分析、定价策略、上市计划 |
| 制造代表 | 可制造性设计、产能规划、生产工艺 |
| 采购代表 | 供应商选择、物料成本、供应链风险 |
| 财务代表 | 投资分析、成本控制、财务预测 |
| 质量代表 | 质量策划、质量保证、质量改进 |
| 服务代表 | 可服务性设计、技术支持、培训 |

## 决策评审（DCP）

DCP是IPD流程中的关键决策点，由IPMT执行，决定是否继续投资。

### 各阶段DCP

| 决策点 | 英文 | 评审内容 | 决策选项 |
|--------|------|----------|----------|
| 概念决策评审 | CDCP | 产品概念是否有价值 | Go / No Go / Redirect |
| 计划决策评审 | PDCP | 计划是否可行、资源是否到位 | Go / No Go / Redirect |
| 开发决策评审 | DDCP | 开发是否完成、质量是否达标 | Go / No Go |
| 可获得性决策评审 | ADCP | 是否具备上市条件 | Go / No Go |
| 生命周期终止决策评审 | LDCP | 是否启动退市 | Go / No Go |

### DCP评审维度
1. **商业吸引力**：市场规模、增长率、盈利能力
2. **竞争地位**：差异化优势、技术领先性
3. **财务回报**：投资回报率、现金流预测
4. **战略匹配度**：与公司战略的契合度
5. **风险可控性**：技术、市场、供应链风险评估

## 技术评审（TR）

与DCP不同，TR是技术层面的评审，确保产品设计满足需求。

| 评审点 | 内容 |
|--------|------|
| TR1 | 产品包需求评审 |
| TR2 | 系统规格评审 |
| TR3 | 概要设计评审 |
| TR4 | 详细设计评审 |
| TR5 | 原型机评审 |
| TR6 | 小批量评审 |

## 矩阵组织的运作要点

- **双线汇报**：PDT成员向LPDT汇报项目工作，向职能部门主管汇报专业能力发展
- **LPDT必须有市场经验**：不能纯技术背景
- **团队共担KPI**：PDT的绩效与产品商业结果挂钩，不是只考核各自部门指标
- **职能部门是"资源池"**：为PDT提供合格的人才和专业能力

## 考核与激励

- **PDT整体考核**：以产品商业成功为核心指标（收入、利润、市场份额、客户满意度）
- **个人考核**：在PDT中的表现 + 专业能力发展
- **激励原则**："绝不让雷锋吃亏"——对跨部门协作中做出贡献的人给予明确认可

## 常见陷阱

- **LPDT纯技术背景**：缺乏市场视角，导致产品技术强但卖不动
- **职能部门不放人**：PDT成员名义上在团队，实际上还在做部门工作
- **DCP流于形式**：评审变成走过场，不能终止坏项目
- **团队缺乏共担意识**：各代表只关心自己部门的指标
- **矩阵变官僚**：多头管理导致效率低下，而不是效率提升
