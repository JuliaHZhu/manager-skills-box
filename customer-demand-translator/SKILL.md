# customer-demand-translator

当用户需要"理解客户真实需求、区分客户说的和真正想要的、将模糊需求转化为可执行产品需求"时激活。
适用于ToB/ToC产品需求分析、解决方案设计、竞品差异化定位、客户需求调研。
不适用于：纯技术实现问题（需求已明确）、无需客户参与的标准化产品生产、内部效率工具（无外部客户）。

Trigger: 客户需求 / 需求分析 / 需求翻译 / 需求转化 / $APPEALS / 痛点 / wants / pains / requirements / 需求层次 / 客户想要 / 产品需求 / 需求管理 / 差异化需求 / 兴奋需求

## 核心方法论

### 一、需求三层次模型

客户告诉你的需求，往往不是真实需求。需求分为三个层次：

| 层次 | 英文名 | 含义 | 特征 | 案例 |
|------|--------|------|------|------|
| **要求** | Requirements | 明确的功能、性能、规格 | 客户已告诉你要什么、怎么做 | "我要一个能在CC08机上切断夜间电话的功能" |
| **想要** | Wants | 客户确定想要，但不确定如何实现 | 主动需求，方向明确、方案模糊 | "苹果需要一个行业最先进的电感，先进到什么程度不知道" |
| **痛点** | Pains | 客户不想要、又不得不解决的东西 | 被动需求，通常来自法规/竞争/内部压力 | 制药厂不想处理环保问题，但牌照制要求必须通过安全环境评审 |

**核心洞察**：
- 客户告知的可能是 requirement，但背后的 want/pain 才是真正的需求
- 把 requirement 和 want 做一一对应，拨开迷雾、去伪成真、去粗取精，这才是供应商的价值所在

### 二、ToB业务需求双维度

**企业需求 vs 岗位（个人）需求**：
- 真正做决策的岗位的需求才是真正的需求
- 企业需求往往很虚，岗位需求才是实的
- 不同角色的需求往往是矛盾的 → 遵循"权力更大原则"

**案例：华为英国运营商2G/3G扩容项目**
- CFO：单位成本必须大幅下降（倾向华为）→ 有一票否决权
- CTO：网络稳定性最高（倾向爱立信）
- 运营总监：降低运维难度、7×24服务（倾向诺基亚）
- 结论：CFO权力最大，需求优先满足

### 三、$APPEALS 八维度需求分析工具

源自IBM，华为引入IPD时采用。用于理解客户需求 + 竞争分析。

| 维度 | 英文 | 核心问题 |
|------|------|----------|
| **$** | 价格/代价 | 客户愿为价值付出的代价（价格只是核心一部分） |
| **A** | 可获得性 Availability | 别人知不知道你的存在？渠道覆盖、品牌曝光 |
| **P** | 包装 Package | 外表包装 + 软件可视化美观感 |
| **P** | 功能性 Performance | 功能、性能、口感、速度、服务温度 |
| **E** | 易用性 Easy to use | 外部易用性 + 内部易用性（制造、仓储、测试） |
| **A** | 保证 Assurance | 前保证（过去安全记录）+ 后保证（出问题赔偿） |
| **L** | 生命周期成本 Life cycle cost | 使用时间成本 + 能源消耗 + 维护成本 |
| **S** | 社会接受度 Social acceptance | 品牌形象、口碑、法律关系、社会责任、环保安全 |

**使用方法**：
1. 对每个维度评估我方 vs 竞争对手的优劣势
2. 根据权重排序发现差距
3. 确定策略，完成需求交付甚至超预期

### 四、需求转化：从客户需求到产品需求

**公式**：
```
产品需求 = 客户问题 + 解决方案
```

**案例**：
- 客户 requirement："CC08机晚上12点到早上8点切断电话"
- 客户真正的问题：有人深夜打电话影响他人休息
- 真正的产品需求：通过行政纪律（谁打电话处罚谁）解决问题，而非技术上切断电话（违反110/119必须畅通的法律要求）

**转化步骤**：
1. 识别客户提出的 requirement
2. 追问背后的 want 或 pain
3. 找到真正的客户问题
4. 设计解决问题的方案（而非直接满足 requirement）

### 五、Kano需求分类（日本经济学家模型）

| 类型 | 特征 | 竞争力影响 |
|------|------|------------|
| **基本需求** Basic | 必须满足，不满足直接淘汰 | 无竞争力加分 |
| **期望需求** Satisfied | 满足程度越高，客户越开心 | 满足越多，竞争力越强 |
| **兴奋需求** Attractive | 不满足可接受，满足了超惊喜 | 差异化竞争力来源 |

**策略**：
- 如果找不到兴奋需求 → 把某些期望需求转换成兴奋需求（如海底捞把服务做成兴奋需求）
- 竞争环境决定：你能做到而别人做不到 → 构建核心竞争力
- 华为策略：投大量研发解决客户的兴奋需求

## 使用步骤

1. **收集需求**：从客户关键岗位收集 requirement / want / pain
2. **需求翻译**：将 want/pain 与 requirement 做一一对应
3. **角色完整**：确保覆盖所有关键决策角色的需求
4. **$APPEALS分析**：八维度评估我方 vs 竞品优劣势
5. **Kano分类**：区分基本/期望/兴奋需求
6. **转化为产品需求**：产品需求 = 客户问题 + 解决方案

## 边界与反模式

❌ **不要**：
- 把客户的 requirement 直接当产品需求（"客户说要什么就做什么"）
- 忽略岗位需求，只看企业需求
- 在需求不完整时就进入产品开发

✅ **要**：
- 永远追问"客户真正的问题是什么"
- 站在客户视角看需求（供应商视角天然小于客户视角）
- 需求来源全面：客户清单 + 竞品对标 + 内部可制造性 + 行业标准
