# 审计威慑体系设计

## R — 原文 (Reading)

> 华为内部审计的超然独立性：任正非对内部审计极为看重，视为有效管理的一种方式。华为设审计部，直接对董事会负责，立足公司管理部门之上，保证了其独立性。
>
> — 华为管理手册, 第51章

> 审计与BC的区别：BC是沿着流程体系进行内控建设，在业务运作中不断闭环实现监控，其执行主体是流程Owner和业务主管；审计是关注"点"的问题，通过对个案的处理建立威慑力量，其执行主体是审计人员。
>
> 审计与稽查的区别：稽查是事中抽查，展开端到端的流程和业务稽查工作，对流程遵从的实质做出评估，查找漏洞；审计是对已出现的问题深入调查，一查到底，并实施问责。
>
> 审计与账务监控的区别：账务体系在全流程每一个监控点上发挥作用，是第一监控者；审计是随机的、随时的、就事论事的，抓一个点就抓死，以形成威慑。
>
> — 华为管理手册, 第54章

> 审计的目标，是为了建立合理的、规范化的经济管理体系和可靠的、最简化的运作程序。要形成不是少数人搞审计，而是每个运行过程都有自动审查、核销。
>
> 全球统一的会计核算和审计监控就像是长江的两道堤坝，只有这两道堤坝足够坚固，财经管理职能才能从容有效的开展。
>
> — 华为管理手册, 第54章 / 任正非

> 华为建立了分层级的三级审计监控体系：(1)业务部门的自我检查；(2)审查部门根据管理规定进行流程审查；(3)根据内部审计制度进行再度审查。
>
> — 华为管理手册, 第51章

> 华为内审早已不局限于财务审计：除财经审计外，还设立了供应链审计、技术支援审计、综合系统审计和国际审计。
>
> — 华为管理手册, 第51章

> 华为内审能与时俱进，紧跟企业发展潮流。随着信息技术推进，相应地增加了信息安全的审计。
>
> — 华为管理手册, 第51章

## I — 方法论骨架 (Interpretation)

华为内部审计的核心定位不是"查账"，而是**建立冷威慑（Cold Deterrence）**——通过独立、随机、深入的个案调查，让所有人都不敢违规。

**审计的本质公式：**
```
业务制造数据 → 会计核算数据 → 审计监督数据 → 财务使用数据
```

**审计与相邻职能的边界：**

| 职能 | 执行主体 | 工作方式 | 核心目标 |
|------|----------|----------|----------|
| **BC（内控）** | 流程Owner + 业务主管 | 沿流程闭环监控 | 流程遵从 |
| **稽查** | 稽查部门 | 事中抽查，端到端评估 | 发现漏洞，帮助改进 |
| **账务监控** | 财务部门 | 全流程监控点，第一监控者 | 揭示风险，执行纪律 |
| **审计** | 审计部（独立） | 随机、随时、就事论事，抓死一个点 | 建立威慑，问责个案 |

**审计只对结果负责，不对行为负责，不对流程负责。**

**三级监控体系：**
1. **第一层 — 业务部门自我检查**：业务主管是内控第一责任人
2. **第二层 — 审查部门流程审查**：对各部门/子公司项目和业务进行流程审查
3. **第三层 — 内部审计独立审查**：从大范围和层面对各大部门进行再度审查

**增值型审计转型：**
- 不止于发现问题，还要站在专业角度提出流程改进建议
- 利用对业务的熟悉度，为企业永续发展出谋划策
- 从"医生"（诊断病症）升级为"营养师"（帮助茁壮成长）

## A1 — 书中的应用 (Past Application)

### 案例 1: 任正非洗衣费被审计
- **问题**: CEO出差日本，将应自付的酒店洗衣费与其他费用一起报销
- **方法论的使用**: 审计部独立发现后约谈任正非，要求退回费用并写检讨
- **结论**: 审计无禁区，最高层也要接受监督；公开案例形成强大文化威慑
- **结果**: 强化了"规则面前人人平等"的组织认知

### 案例 2: EMT成员审计与饭费报销
- **问题**: EMT成员与下属就餐，不知被谁买了单又拿去报销
- **方法论的使用**: 审计就"一顿饭"追查到底——在哪儿吃的、吃了什么、给照片确认
- **结论**: 审计的"30%原则"：找到一个点，就从头查到底，把细节查清楚，形成方法论威慑
- **结果**: 2018年任正非被罚100万，三位轮值董事长各罚50万

### 案例 3: 审计范围扩展到信息安全
- **问题**: 企业信息化带来新风险
- **方法论的使用**: 综合系统审计从研发/营销/行政扩展到信息安全审计
- **结论**: 审计必须与时俱进，随企业发展不断扩大范围
- **结果**: 企业运行环境更加安全

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **诊断现有审计状态**
   - 完成标准: 明确审计向谁汇报、是否独立于业务、审计范围是否局限于财务

2. **设计审计组织架构**
   - 完成标准: 审计部直接对董事会/审计委员会负责，不设于CFO之下
   - 设立多维度审计团队：财经审计、供应链审计、技术审计、综合系统审计、国际审计

3. **明确审计与相邻职能边界**
   - 完成标准: 与业务部门、BC内控、稽查部门、账务部门签署职能边界协议
   - 关键规则：审计不替代业务主管的内控责任，不替代稽查的事中抽查，不替代账务的流程监控

4. **建立三级监控体系**
   - 完成标准: 第一层（业务部门自检）→ 第二层（审查部门流程审查）→ 第三层（审计独立审查）
   - 监控点下移到具体业务流程，实现例行化自动审查

5. **设计审计工作方式**
   - 完成标准: 随机+随时+就事论事，抓一个点查到底
   - 采用"30%原则"：找到一个问题彻底查清，形成方法论威慑
   - 审计报告需经项目经理→主管→部门主管多层评审，大项目上升到董事会

6. **推动增值型审计转型**
   - 完成标准: 审计结论不仅包含问题定性，还包含流程改进建议
   - 审计人员考核温和化，不设项目奖金，避免与业务形成对立

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 外部法定审计 — 那是会计师事务所的事
- 纯合规 checklist 检查 — 用合规管理skill
- 没有董事会/最高层支持的情况下推进审计独立化 — 审计独立必须自上而下
- 微型企业（<50人）— 不需要专门审计部门

### 作者在书中警告的失败模式

- **审计成为业务警察**: 审计人员工作方式不当，变成威胁而非威慑，干扰业务
- **审计结论重文本不重实质**: 基于后端问题定性前端流程不遵从
- **审计"举一反三"过度**: 就事论事变成无限上纲上线
- **审计与业务对立**: 审计有项目奖金激励，导致故意找茬

### 作者的盲点 / 时代局限

- 华为审计体系基于大型跨国企业设计，中小企业可采用"外包审计+关键岗位轮换"替代
- 数字化时代，审计可更多利用数据分析实现持续审计（Continuous Auditing），而不仅依赖随机抽查

### 容易混淆的邻近方法论

- 与稽查: 稽查是"事中抽查帮改进"，审计是"事后查死建威慑"
- 与BC内控: BC是"流程Owner的责任"，审计是"独立评估"
- 与纪检监察: 纪检监察处理人事，审计处理事实
