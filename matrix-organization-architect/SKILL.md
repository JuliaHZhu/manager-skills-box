## Core Methodology

Huawei's matrix organization is a deliberate "binary structure" — static vertical (functional departments for talent cultivation) + dynamic horizontal (process/project teams for customer delivery). The architect balances three root causes that demand a matrix.

### Why Matrix: Three Root Causes

1. **Empower the frontline (授权一线员工)**
   - In functional orgs, frontline staff have no authority; they escalate everything.
   - In a matrix, the frontline becomes "one-dragon managers" (一条龙经理) who own end-to-end process outcomes.
   - Examples: customer-service manager, product manager, solution manager, delivery manager — all are previously ordinary staff now empowered as process owners.

2. **Grayscale equilibrium (灰度均衡的二元组织)**
   - Pure project teams lose sustainable talent pipelines; pure departments lose customer responsiveness.
   - John Kotter's "dual operating system": static vertical for capability building + dynamic horizontal for market responsiveness.
   - Departments cultivate people; processes consume people. The matrix ensures both.

3. **Talent reuse (人才复用)**
   - Project-type orgs trap people inside one project; matrix allows one employee to serve N projects simultaneously.
   - Employees belong administratively to departments, but are dispatched to multiple project teams.
   - Eliminates idle peaks and valleys in staffing.

### Three Matrix Types

| Type | Horizontal Power vs Vertical Power | When to Choose |
|------|-----------------------------------|----------------|
| **Weak matrix** | Horizontal << Vertical. Project manager is only a coordinator. | Avoid — it is a "fake matrix." |
| **Balanced matrix** | Horizontal ≈ Vertical. Equal authority in考核 and resource allocation. | Default target for most enterprises. |
| **Strong matrix** | Horizontal >> Vertical. Project manager has greater say than functional manager. | When customer responsiveness is the overriding priority. |

Huawei prefers strong matrix for customer-facing flows, balanced matrix for support flows.

### Transformation Path: Process First, Then Org

Matrix cannot be drawn on paper; it must grow through capability.

**Step 1 — Process transformation**
- Redesign functional silo processes into end-to-end, customer-value-centered flows.
- Forget departments; think flows. Return to the most natural state that satisfies customer needs.

**Step 2 — Organization transformation (four pillars)**

1. **Key talent capability building**
   - Functional departments are 100% responsible for matrix success. If they fail to cultivate people, the matrix collapses.
   - Department heads must shift from "doing work themselves" to "cultivating people to do work."
   - Build qualification systems, talent pools, and干部 resource pools.
   - Focus especially on横向 talent (cross-functional generalists).

2. **Team building**
   - All horizontal work is project-based, not administrative-line based.
   - Define team goals, responsibilities, communication protocols, and decision mechanisms.

3. **Committee construction**
   - Horizontal teams report to committees, not to functional bosses.
   - Committee functions: decision-making, strategic direction, resource arbitration.
   - Without committees, one-dragon managers become orphans.

4. **Assessment and incentive redesign**
   - Vertical: department KPIs (still needed but insufficient).
   - Horizontal: process/project performance metrics + project bonuses.
   - Form a dual考核-and-incentive system.

### Managing the 1+N Reporting Relationship

In a matrix, every employee has:
- **1** administrative leader (department head) — responsible for growth, training, and career development.
- **N** project/horizontal leaders — responsible for task execution and dynamic allocation.

Common concern: "Isn't dual reporting confusing?"
- In reality, 1+N means the employee faces customer requirements more directly instead of being controlled by a single boss.
- Scheduling discipline resolves conflicts: e.g., Monday morning with department head, Monday afternoon in Project A, Tuesday in Project B.

### Anti-patterns to Avoid

- **阿米巴 without matrix** — treating every unit as independent profit center destroys shared platforms.
- **Eliminating departments entirely** — losing the talent factory.
- **Weak matrix** — calling it matrix while real power stays in functional silos.
- **Drawing boxes first** — matrix must grow from流程 maturity, not from an org chart exercise.

## Activation Protocol

1. **Diagnose current org type** — functional? weak matrix? project-type?
2. **Select matrix strength** — strong, balanced, or hybrid by flow type.
3. **Map end-to-end flows** — identify customer-to-customer value chains.
4. **Design committee structure** — one committee per core end-to-end flow.
5. **Define 1+N rules** — clarify when department lead decides vs when project lead decides.
6. **Redesign incentives** — introduce project-level考核 and bonuses alongside departmental KPIs.

## STOP Checkpoint

Before finalizing the matrix design, verify:
- [ ] Have end-to-end processes been redesigned first?
- [ ] Is there a committee backing each major horizontal flow?
- [ ] Are functional departments ready to shift from "doing" to "cultivating"?
- [ ] Is the incentive system dual (vertical + horizontal)?
- [ ] Have we avoided weak-matrix traps where project managers are mere coordinators?

## Output Format

When activated, provide:
1. A **matrix-type recommendation** with rationale.
2. A **flow-to-team mapping** for the user's core value chains.
3. A **committee charter template** for the most critical flow.
4. A **1+N decision-rights table** showing who decides what.
5. A **dual-incentive outline** with vertical and horizontal weights.
