# IT治理架构与投资决策

基于华为信息化治理实践，IT治理的核心是**让IT投资产生最大业务价值**，通过架构管控避免重复建设，通过分层决策提升效率，通过绩效衡量证明价值。

## 一、IT治理体系五大部分

### 1. 战略规划与决策体系
- **三年滚动规划**：每年看后3-5年业务变革与信息化建设规划
- **与商业计划对锁**：长期关注与短期聚焦结合
- **规划内容**：业务变革举措 + 业务流程举措 + IT举措 → 管理流程和IT需求 → IT业务服务
- **华为实践**：2004年开始实施五年战略规划，每年重新往后五年滚动，并与当年商业计划对锁

### 2. 企业架构管控（EA）
- **架构三层**：
  - **业务架构**：基于业务战略应该具备哪些业务能力，在此基础上流程化
  - **信息架构**：IT系统如何支撑、数据如何流转
  - **技术架构**：底层技术如何实现、应用系统之间的关系
- **架构需求来源**：国家政策法规、公司内部新业务模式、业界最佳实践、技术发展趋势、痛点需求
- **管控目标**：避免重复建设和无人管的问题

### 3. 分层分级决策体系
- **最高层**：RSC变革指导委员会（公司级重大变革决策）
- **集团层**：C-3T集团决策团队（跨流程跨子公司的决策）
- **业务层**：每个议程流程都有相应的业务变革和IT团队（领域内决策）
- **流程层**：流程责任人体系（BPO + 流程审计部）
- **企业架构层**：企业架构委员会（架构评审）

### 4. 项目管理体系
- **软件包实施**：业界有匹配度70-80%的软件包就直接上
- **应用开发**：遵从CMMI体系（华为通过CMMI 4级认证）
- **版本火车管理**：针对碎片化IT需求，一年开四趟版本火车
  - 把需求归到相应版本，进版本的交付，没进版本的坐下来商量
  - 无序需求变成有序管理

### 5. IT运维管理体系
- **基于ITIL v3.0构建IT业务服务管理体系（BSM）**
- **三面向**：
  - 面向用户：提高服务水平、关键业务保障、客户满意度
  - 面向设备：自动化操作、性能/容量/故障数据
  - 面向管理层：运作结果可视化、高效稳定可靠

## 二、IT投资决策：谁受益，谁承担

### 核心原则
- **大原则**：谁受益，谁承担
- **公司级投资**：网络、数据中心等公共基础设施，ERP等公司级应用由公司做预算和投资，完成后按BG收益分摊
- **部门级投资**：业务部门自己一定要建的系统，自己出钱，但要备案
- **好处**：减少内部吵架，让投资与收益挂钩

### ROI评估与分层决策
- **一线部门、业务部门、IT部门每月坐在一起评估需求**
- **从整体架构角度评估项目**
- **最终投票通过的需求提交到更高层级的变革指导委员会审批**
- **关键规则**：仅仅着眼于局部优化的项目不会被通过，必须达到全局优化

### IT预结算管理
- 预算资金来源明确
- 按BG/区域/产品线分摊公共IT成本
- 自建系统成本自担

## 三、平衡计分卡衡量IT价值

### 四个维度

| 维度 | 指标示例 | 华为实践 |
|------|----------|----------|
| **财务** | IT项目ROI、IT Cost/Revenue、运维费用率 | IT投资占销售收入1%-1.5% |
| **客户** | 系统可用性SLA（99.95%）、数据不丢失承诺、关键业务保障、内部满意度 | 业务对IT满意度达87.22分历史最好 |
| **内部运营** | 重要IT项目及时交付率、IT内控成熟度 | 需求端到端交付周期下降3倍 |
| **学习与成长** | IT资源效率、人均服务比 | IT与流程人均服务比1:100 |

### 满意度考核机制
- 每年9月由HR部门发起对IT部门的满意度调查
- 如果满意度分数没有达到年度承诺值，**部门奖金受影响**

## 四、业务流程架构：六级分层

### 分层目的
- 更好地管理流程
- 对责任进行划分
- 写软件包时一般做到L3-L4

### 六级架构
| 层级 | 名称 | 特点 |
|------|------|------|
| L1 | 流程分类 | 覆盖全部业务，支撑战略，固定不变 |
| L2 | 流程组 | 聚焦战略设计，主业务流程，固定不变 |
| L3 | 流程 | 聚焦战略执行，固定不变 |
| L4 | 子流程 | 具体业务流程，相对稳定 |
| L5 | 活动 | 具体活动，灵活，因地制宜 |
| L6 | 任务 | 具体任务，灵活，因地制宜 |

### 端到端流程贯通
- 从客户需求到最后交付给客户
- 三个集成：
  1. 价值链集成（需求管理→供应链→采购→制造→工程管理→服务）
  2. 财务融于业务（IFS：合同收款、验收开票、资金流）
  3. 价值网络横向集成

## 五、变革项目管理机制

### 项目生命周期
概念 → 计划 → 开发 → 验证 → 推行 → 生命周期管理

### 关键控制点
1. **概念阶段结束**：决策体系根据项目层级做商业决策
2. **开发验证完**：试点通过后再全球推广
3. **技术评审**：技术和架构要经过专业评审，不可行要写明理由

### 需求梳理流程
- 中长期需求 → 变革规划输入
- 短期需求 → 划到相关项目组
- 商业决策前必须经过技术和架构评审

## 六、IT服务管理：C.R.S.A模式

### 全球运维四化
1. **集中化**：全球IT资源集中管控
2. **例行化**：把变更工作例行化
3. **标准化**：标准化后才能脚本化、自动化
4. **自动化**：减少运维人员，远程维护，提高效率

### IT业务服务管理（BSM）
- **服务规划**：面向业务的服务目录
- **服务交付**：统一服务台、用户服务中心、现场服务、专家支持中心
- **服务监控**：业务交易监控、业务影响分析、业务体验管理
- **服务仪表板**：综合信息发布、管理决策报表
- **SLA管理**：服务水平承诺、客户满意度
