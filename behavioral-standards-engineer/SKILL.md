# behavioral-standards-engineer — 行为标准工程师

## R (Reading) — 原文引用

> "华为文秘体系早在1998年即引进英国NVQ(National Vocational Qualification)文秘(行政管理)职业标准体系，是华为任职最早推行和完善的体系之一。"（Ch26.1）

> "行为标准按单元组织，每个单元包含若干要素，每个要素下列出具体的行为要求。"（Ch24.3）

> "要素1.1 组织你自己的工作：A、运用适当的工作方法，最有效地利用时间；B、使自己的工作和同事的工作协调一致；C、最大限度地控制材料的浪费；D、根据既定的工作程序开展工作。"（Ch24.3）

> "【第一单元要素必备知识范围】时间管理知识、组织个人工作的方法、与上司同事沟通的技巧和协作方法、公司及部门的安全保密制度。"（Ch24.3）

> "助理类要素4.1 按要求起草文件：A、明确需起草文件或信函，并按紧急重要程度优先处理；B、准确理解文件的要求及将达到的预期效果；C、核查文件所依据的信息来源是否确切和有效；D、按起草的内容正确使用文种，措词准确、表达清晰。"（Ch24.5）

> "认证重点：能否客观认识自己、评价自己；工作计划的制定、执行、调整；敏锐发现主管需求，并提供相应信息。"（Ch24.5）

## I (Interpretation) — 方法论骨架

行为标准（Behavioral Standards）与岗位职责（Job Description）的根本区别：

| 维度 | 岗位职责（JD） | 行为标准（BS） |
|------|---------------|---------------|
| 聚焦 | 做什么（Tasks） | 做到什么程度（Performance） |
| 动词 | 负责、组织、参与 | 协调、推动、确保、优化 |
| 可观察性 | 低（"负责文档管理"） | 高（"在24小时内将文档分类存储到指定位置并更新索引"） |
| 衡量方式 | 是否做了 | 做得怎样、多快、多好 |
| 用途 | 招聘、分工 | 认证、晋升、培训 |

华为秘书任职资格的行为标准设计遵循**"单元-要素-行为-知识"四级结构**：

```
工作单元（Unit）
├── 要素（Element）
│   ├── 行为描述（Behavior）
│   │   ├── A级：高难度/高价值行为
│   │   ├── B级：中高难度行为
│   │   ├── C级：中等难度行为
│   │   └── D级：基础行为
│   └── 必备知识（Knowledge）
│       ├── 公司制度/流程
│       ├── 工具/系统使用方法
│       └── 专业知识/技能
└── ...
```

**NVQ本土化经验**：
- 英国NVQ强调"基于证据的评估"（Evidence-based Assessment）
- 华为将其转化为"行为标准认证"，结合知识考试和绩效审查
- 核心改造：将英国标准中的通用描述，替换为华为具体的制度、流程、工具名称

## A (Application) — 执行步骤

### 步骤1：从任务清单到能力要素

**输入**：该岗位的日常任务清单（可通过访谈、观察、工作日志获得）

**转化方法**：
```
任务清单 → 按工作领域聚类 → 提取能力要素 → 按难度分级

示例：
任务：接打电话、收发邮件、管理日程、安排会议、整理文档...

聚类：
- 沟通协作类：接打电话、收发邮件、接待访客
- 信息管理类：管理日程、整理文档、维护数据库
- 会务支持类：安排会议、准备资料、记录纪要
- 资源管理类：申购办公用品、管理固定资产

提取要素（以"会务支持类"为例）：
- 会议前准备
- 会议中协助
- 会议后整理
```

**STOP检查点1**：如果聚类后某个"单元"里只有1个要素，说明聚类太细，应合并；如果超过5个要素，说明聚类太粗，应拆分。

### 步骤2：为每个要素写分级行为描述

**核心原则**：行为描述必须回答三个问题——
1. **对象**：对谁做？（客户/同事/主管/系统）
2. **动作**：做什么？（可观察的行动动词）
3. **标准**：做到什么程度？（时间/质量/数量要求）

**动词选择表**：

| 级别 | 认知类（避免） | 行动类（推荐） |
|------|--------------|--------------|
| 初级 | 了解、知道、熟悉 | 执行、操作、传递、记录 |
| 中级 | 掌握、理解 | 协调、检查、提醒、优化 |
| 高级 | 精通、深刻认识 | 设计、推动、培训、监控 |

**华为秘书示例**：

| 级别 | 行为描述（要素：会议前准备） |
|------|---------------------------|
| 1级 | 根据通知要求，准备会议室和基本设备 |
| 2级 | 明确会议目的和议程，确认与会人员，提前测试设备 |
| 3级 | 根据议题准备相关资料，预判特殊需求，制定应急预案 |

**STOP检查点2**：如果去掉级别标签，评委无法判断哪个是高级行为、哪个是初级行为，说明分级不明显，需要重写。

### 步骤3：设计认证重点

每个要素应明确"认证重点"——评委在评议时最关注什么：

```
要素示例：计划和组织个人工作进度表
认证重点：工作计划的制定、执行、调整

评议时关注：
- 是否制定了工作计划？
- 计划是否合理（考虑了轻重缓急）？
- 是否按计划执行？
- 遇到变化时如何调整？
```

**认证重点设计原则**：
- 每个要素的认证重点不超过3个
- 认证重点应是可观察、可举证的
- 认证重点应能区分不同级别的差异

### 步骤4：提取必备知识

每个单元末尾列出支撑该单元行为的**知识清单**：

**提取方法**：
1. 对每条行为描述问："要做到这个，需要知道什么？"
2. 将知识按类别整理：制度类、工具类、技能类
3. 去重和精简，每个单元的必备知识控制在10条以内

**华为秘书示例（第一单元：提高工作效率）**：
- 时间管理知识
- 组织个人工作的方法
- 与上司、同事沟通的技巧和协作方法
- 社会公布的火警、匪警、急救等电话号码
- 告警系统的操作方法、灭火器材的使用方法
- 初步的护理知识
- 上报紧急情况的方法及流程
- 公司及部门的安全、保密制度

### 步骤5：本土化改造（如基于国际标准的适配）

如果基于国际职业标准（如NVQ、SHRM等）进行本土化，遵循**"结构保留、内容替换"**原则：

| 维度 | 保留（国际标准的框架） | 替换（本土化的内容） |
|------|---------------------|-------------------|
| 单元划分 | 按工作领域划分 | 保留结构，按本公司岗位调整名称 |
| 要素结构 | 每个要素下有分级行为 | 保留结构，重写行为描述 |
| 评估方式 | 基于证据的评估 | 保留理念，调整证据类型和认证流程 |
| 必备知识 | 列出知识范围 | 替换为本公司的具体制度、工具、流程 |

**本土化检查清单**：
- [ ] 所有提到的制度/流程名称是否已替换为本公司的？
- [ ] 所有提到的工具/系统是否已替换为本公司实际使用的？
- [ ] 行为描述中的标准是否符合本公司的实际要求？
- [ ] 认证方式是否符合本公司的管理文化和资源条件？

## ⚠️ Anti-Example 黑名单

- ❌ 行为描述使用认知动词（"了解""熟悉""掌握"）而非行动动词
- ❌ 行为描述写成岗位职责（只写"负责XX"不写"做到什么程度"）
- ❌ 各级别行为之间没有明显难度递进（初级和高级写得差不多）
- ❌ 必备知识罗列过多过杂（超过10条/单元）
- ❌ 直接翻译国际标准而不做本土化（导致标准与实际工作脱节）

## 📋 Failure-Mode Fallback

| 如果用户... | 则... |
|------------|-------|
| 写不出行为描述 | 先收集该岗位的3-5个"优秀员工"和"不合格员工"的具体案例，对比提取行为差异 |
| 行为标准太琐碎 | 聚焦"关键行为"——区分优秀与平庸的核心差异行为，非核心行为可省略 |
| 不同评委对同一行为的评级不一致 | 增加"认证重点"和"举证要求"，减少主观判断空间 |
| 国际标准与本公司差异太大 | 只借鉴其"结构和方法论"，内容全部重写；不要试图"适配"相差太远的标准 |
| 员工觉得行为标准像"监视" | 强调行为标准的作用是"帮助员工清晰知道做到什么程度可以晋升"，而不是抓把柄 |

## T (Test) — 验证问题

- 随机抽取一条行为描述，去掉级别标签，3个不同评委能否独立判断它属于哪个级别？
- 一位该岗位的优秀员工，能否在每条高级行为上举出至少2个近期实例？
- 一位该岗位的初级员工，能否清晰理解自己当前在哪一级、下一级需要做什么？
- 如果把这套标准给一个没有见过该岗位工作的人，他能否根据标准判断一个员工的行为水平？
