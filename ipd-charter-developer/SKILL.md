# IPD Charter 开发方法论

基于华为IPD体系，Charter（项目任务书）开发是一项独立的、被严格管理的创新活动。核心原则：**像开发产品一样开发Charter**。

## 核心思想

- **Charter开发不是写文档，是开发商业计划**：Charter的质量决定项目的生死，是"做正确的事"的关键环节
- **端到端团队参与**：Charter开发团队（CDT）必须包含市场、研发、供应链、财务、服务等跨领域代表
- **商业计划驱动**：Charter的核心是回答"这个项目值不值得投"，而非"这个技术能不能做"
- **渐进明细**：Charter本身是逐步完善的，从初始Charter到目标Charter需要多轮迭代

## Charter开发流程（CDP）

### 阶段1：项目需求分析
1. **市场需求收集**：$APPEALS分析（价格、可获得性、包装、性能、易用性、保证、生命周期成本、社会接受度）
2. **竞争分析**：竞品功能/性能/价格对比
3. **技术可行性初判**：核心技术是否ready，是否有专利风险
4. **商业模式初判**：B2B需考虑客户投资回报率，B2C需考虑市场规模

### 阶段2：初始Charter开发
输出《初始Charter》，包含：
- 产品愿景与目标市场
- 关键客户需求（排序）
- 初步商业目标（收入、利润、市场份额）
- 关键技术路线
- 资源需求概算
- 风险初识

### 阶段3：目标Charter开发
通过多轮评审迭代，输出《目标Charter》，在初始Charter基础上增加：
- 详细的商业计划（5年财务预测）
- 完整的产品包需求（功能+性能+可靠性+可服务性+可制造性）
- 项目里程碑与资源计划
- 详细的竞争策略
- 风险评估与应对计划

### 阶段4：Charter评审与决策
提交IPMT（集成产品管理团队）进行Charter DCP（决策评审点），评审维度：
1. **市场吸引力**：市场规模、增长率、竞争格局
2. **竞争地位**：差异化优势、进入壁垒
3. **财务回报**：NPV、IRR、投资回收期
4. **战略匹配度**：与公司战略/产品线战略的契合度
5. **风险可控性**：技术风险、市场风险、供应链风险

## Charter质量标准

- **市场需求覆盖度**：是否覆盖了目标客户的核心痛点
- **商业逻辑自洽**：收入预测、成本结构、定价策略是否逻辑一致
- **可执行性**：资源、时间、技术路线是否现实可行
- **端到端视角**：是否考虑了从研发到上市到服务的全生命周期

## 常见陷阱

- **技术导向**：Charter写成了技术方案，没有商业论证
- **需求泛化**：试图满足所有人，结果没有差异化
- **乐观偏差**：收入和进度预测过于乐观，风险被低估
- **闭门造车**：没有市场人员参与，纯研发视角
