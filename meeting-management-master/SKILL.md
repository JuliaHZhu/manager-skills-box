# meeting-management-master — 会议管理全流程方法论

## R (Reading) — 原文引用

> "办会做到‘三要点、三服务、三件事’，即会前有‘三要点’（议题、资料、通知），会中有‘三服务’（签到、记录、服务），会后做‘三件事’（纪要、督办、费用）。"（Ch13.1）

> "会议通知做到‘五明确’：明确会议时间（开始时间、结束时间）、明确会议地点（楼层、会议室名称）、明确会议议题（议题顺序、汇报人、汇报时间）、明确参会人员（出席、列席、请假权限）、明确会议要求（着装、资料、准备）。"（Ch13.2.2）

> "会议资料要提前准备，避免会上‘现炒现卖’。"（Ch13.2.3）

> "签到不是形式，而是确认‘谁来了、谁没来、为什么没来’，以便及时通知和后续追责。"（Ch13.3.1）

> "会议记录要做到‘原汁原味’，不能随意增删改。"（Ch13.3.2）

> "会议纪要要在24小时内发出，否则会议效果大打折扣。"（Ch13.4.1）

> "会议决议要‘一对一’落实到责任人，避免‘大家负责就是没人负责’。"（Ch13.4.2）

> "会议费用要及时结算，避免‘小账变大账’。"（Ch13.4.3）

> "办会‘查三遍’：会前查准备、会中查纪律、会后查落实。"（Ch13.5）

## I (Interpretation) — 方法论骨架

会议是组织最大的隐性成本之一。一个低效会议的成本 = 参会人数 × 平均时薪 × 会议时长 + 准备时间 + 后续返工时间。

华为会务管理的核心是**"三阶段闭环"**：

```
会前（三要点）
├── 议题：明确开什么会、解决什么问题、需要什么决策
├── 资料：提前分发、提前阅读、会上不念稿
└── 通知：五明确（时间/地点/议题/人员/要求）

会中（三服务）
├── 签到：确认出席情况，实时通知变动
├── 记录：原汁原味记录发言和决议
└── 服务：设备、茶水、突发情况处理

会后（三件事）
├── 纪要：24小时内发出，决议清晰可执行
├── 督办：一对一落实责任人、时间节点
└── 费用：及时结算，避免积压
```

**另一维度的质量控制**：办会"查三遍"
- **会前查准备**：设备、资料、人员、场地是否到位
- **会中查纪律**：是否跑题、是否超时、是否有人玩手机
- **会后查落实**：决议是否被执行、问题是否被解决

## A (Application) — 执行步骤

### 步骤1：会前筹备（三要点）

#### 要点1：议题设计

**STOP检查点1**：如果一个会议没有明确的决策项，它不应该是一个会议，而应该是一封邮件或一个文档。

议题设计模板：
```
会议名称：[部门/项目]第X周例会 / [主题]专题研讨会
会议目的：（本次会议要解决什么问题？）
议题列表：
  1. [议题名称] — 汇报人：[姓名] — 时长：[X分钟] — 决策项：[需要做什么决定]
  2. ...
预计时长：[总时长，建议不超过90分钟]
```

**议题数量控制**：
- 决策型会议：1-3个议题（深度讨论）
- 信息同步型会议：5-8个议题（快速过）
- 超过5个决策议题 → 拆分为多个会议

#### 要点2：资料准备

资料分发规则：
- **决策型会议**：资料提前48小时发出，要求参会人提前阅读并准备意见
- **紧急会议**：至少提前2小时发出核心数据和分析
- **会上禁止**：首次展示长篇PPT、现场翻阅资料

**资料质量控制**：
- 每份资料首页必须有"结论先行"（Executive Summary）
- 数据必须有来源和更新时间
- 方案类资料必须提供选项对比，而不是只推荐一个方案

#### 要点3：通知发送

会议通知"五明确"检查清单：
- [ ] 时间明确：开始时间、结束时间（不要只写"下午开会"）
- [ ] 地点明确：楼层、会议室名称（线上会议写明链接和密码）
- [ ] 议题明确：议题顺序、汇报人、每个议题的预计时长
- [ ] 人员明确：必须出席、可以列席、谁有权请假
- [ ] 要求明确：着装、需要提前看的资料、需要准备的数据

**通知发送时间**：
- 常规会议：提前3个工作日
- 重要会议：提前1周
- 紧急会议：提前2小时（但紧急会议比例应控制在10%以内）

### 步骤2：会中管理（三服务）

#### 服务1：签到与出席管理

- 会议开始前5分钟确认出席情况
- 未到人员立即联系确认原因
- 关键决策人未到 → 会议延期或改为信息同步（不决策）

#### 服务2：记录与纪律

**记录分工**：
- 专人记录：大型会议、决策型会议
- 轮流记录：小型例会
- 不记录：头脑风暴会（会后整理要点即可）

**记录要点**：
- 原汁原味记录关键发言（尤其是反对意见）
- 明确记录每个决议的"是什么"和"谁负责"
- 不记录闲聊、重复发言

**纪律维护**：
- 有人跑题 → 提醒"这个话题我们可以会后再讨论"
- 有人超时 → 提醒"我们还有X分钟，请总结结论"
- 有人看手机 → 视会议重要性，必要时点名提醒

#### 服务3：现场服务与应急

- 设备故障：提前15分钟到场测试，准备备用方案
- 茶水服务：长会（>1小时）提供茶水，短会不提供（避免打断）
- 突发情况：主持人/秘书有权暂停会议处理紧急事务

### 步骤3：会后闭环（三件事）

#### 第一件事：会议纪要

**时效**：24小时内发出（最好当天）

**纪要模板**：
```
会议纪要
会议主题：[标题]
时间：[日期时间]
地点：[地点]
出席：[名单]
缺席：[名单及原因]

一、决议事项
  1. [决议内容] — 责任人：[姓名] — 完成时间：[日期]
  2. ...

二、待跟进事项
  1. [事项] — 责任人：[姓名] — 完成时间：[日期]
  2. ...

三、信息同步（无需行动）
  1. ...

记录人：[姓名]
发送时间：[日期]
```

**STOP检查点2**：如果会议纪要发出后还有人问"会上决定什么了"，说明纪要写得不够清晰。

#### 第二件事：督办跟踪

**督办机制**：
- 简单版：会议纪要中的决议事项，到期前一天提醒责任人
- 标准版：建立会议决议跟踪表，每周更新进度
- 高级版：下次会议的第一个议题是"上次决议落实情况"

**责任落实原则**：
- 每个决议必须有且只有一个主要责任人
- 避免"XX部门负责"——要具体到人
- 完成时间必须是具体日期，不能是"尽快""下周"

#### 第三件事：费用结算

- 外部场地/餐饮/交通费用：3个工作日内完成报销
- 内部成本分摊：月底统一结算
- 避免"小账变大账"——积压费用会导致遗忘和纠纷

### 步骤4：质量检查（查三遍）

**会前查准备**（会议开始前30分钟）：
- [ ] 投影/屏幕正常
- [ ] 音响/麦克风正常
- [ ] 资料已打印/已共享
- [ ] 座位和名牌已摆放
- [ ] 茶水/设备已到位
- [ ] 关键参会人已确认出席

**会中查纪律**（会议进行中）：
- [ ] 按议程进行，未严重超时
- [ ] 参会人注意力集中
- [ ] 记录完整
- [ ] 决议清晰

**会后查落实**（会议结束后1周/1月）：
- [ ] 纪要已发出并被确认收到
- [ ] 决议事项已开始执行
- [ ] 到期事项已完成
- [ ] 未完成的已说明原因并重新设定期限

## ⚠️ Anti-Example 黑名单

- ❌ 为开会而开会（没有明确议题和决策项）
- ❌ 会上首次展示长篇资料（会上应该是讨论，不是阅读）
- ❌ 会议纪要写成流水账（记录所有发言，没有提炼决议）
- ❌ 决议没有责任人和时限（"大家回去落实一下"）
- ❌ 会议结束后没有任何跟进（开完就忘，下次再开同样的会）

## 📋 Failure-Mode Fallback

| 如果用户... | 则... |
|------------|-------|
| 会议太多，根本开不完 | 先做会议审计：列出所有定期会议，砍掉没有明确决策项的、合并议题重叠的 |
| 参会人不看提前发的资料 | 缩短会议时间，明确"资料已提前发，会上只讨论不念稿"；对不提前阅读的人，会上不重复解释 |
| 会上总是跑题 | 指定主持人严格控场，设置"停车场"（把跑题话题记下来，会后专门讨论） |
| 决议总是落实不了 | 检查是不是决议本身不清晰、责任人太多、或者没有跟踪机制 |
| 线上会议效率更低 | 要求全员开摄像头（提高注意力），主持人频繁点名互动，每20分钟休息一次 |

## T (Test) — 验证问题

- 你们组织的会议中，有多少比例在24小时内发出了纪要？
- 随机抽查上次会议的3个决议，现在有2个已经完成并且质量达标吗？
- 如果你的会议减少50%，组织运转会受到什么影响？如果答案"没什么影响"，说明这些会本就不该开。
