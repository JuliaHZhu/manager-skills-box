# red-blue-debater — 红蓝对抗战略辩论机制

## R (Reading) — 原文引用

> "蓝军要想尽办法来否定红军。等到红军和蓝军打得差不多的时候，任正非最后出来做决定。其实这个时候往左走往右走已经不那么重要了，公司要的是一个方向。"（Ch1.2）

> "在制定战略期间，蓝军和红军之间互相PK搞辩论，通常持续好几个月。"（Ch1.2）

> "采用辩论、模拟实践、战术推演等方式，对当前的战略思想进行反向分析和批判性辩论。"（Ch1.2）

> "红军评委会有任期制，避免评审体系老化；蓝军和红军要有置换，优秀的蓝军可以做红军司令。"（Ch18.1）

> "我不管无线在蓝军上投资多少，但一定要像董事《炮轰华为》一样，架着大炮轰。"（Ch12）

## I (Interpretation) — 方法论骨架

红蓝对抗不是"开会吵架"，而是一套**结构化的决策压力测试机制**。其本质是：在投入大量资源执行前，先投入相对少量的资源进行"预演性否定"，从而暴露战略盲区。

**核心设计原则**：

1. **方向 > 左右**：红蓝对抗的目的不是"选A还是选B"，而是确保"方向大致正确"。最终决策者拍板时，往左往右已不重要。
2. **时间投资**：好的对抗需要"好几个月"，不是一两个小时的形式主义。
3. **人格分离**：红军和蓝军是角色，不是人。同一个人可以在不同议题上切换角色。
4. **任期制**：红军评委会1/3定期更替，防止评审体系老化、思维固化。
5. **允许平局**：蓝军"否不掉"也是价值——动了脑筋的批判过程本身就是对战略的一次加固。

**对抗的三种形式**：
- **辩论式**：正反双方就同一议题进行结构化辩论
- **模拟实践式**：蓝军模拟竞争对手的反击策略
- **战术推演式**：沙盘推演，预判各路径的风险与机遇

## A1 (Past Application) — 书中案例

**华为终端业务保卫战（2008年）**：
- 背景：华为计划将终端业务出售给贝恩资本
- 蓝军动作：经过大量调研，拿出1页纸报告
- 核心论点："未来的电信行业将是端-管-云三位一体，终端决定需求，放弃终端就是放弃华为的未来"
- 结果：任正非拍板保留终端业务，十年后终端业务占华为总营收近50%

**华为无线产品线蓝军（2013年）**：
- 任正非要求："架着大炮轰"，发表文章按进入邮箱顺序排列
- 方法论："一定要把华为公司的优势去掉，去掉优势就是更大的优势"
- 结果：两军互攻产生"井喷"，井喷出的东西可能就是机会点

**华为战略规划节奏**：
- 春季计划（6月前）：未来3年战略规划，红蓝PK数月
- 秋季计划（9月前）：基于3年规划制定次年计划
- 预算分解（12月前）：目标分解

## A2 (Future Trigger) — 何时调用

- 年度/季度战略规划会前，需要设计反向论证环节
- 重大投资决策（并购、 divestiture、大额研发投入）前
- 产品方向分歧大、高层意见不统一时
- 感觉"这个决策太顺了"——所有人都同意，反而需要蓝军挑战
- 新业务孵化 vs 传统业务防守的资源分配争议

## E (Execution) — 可执行步骤

### Step 1: 议题选择

好的对抗议题必须具备以下特征：
- **高 stakes**：决策失误代价高（至少影响未来1-2年的资源分配）
- **方向性**：不是操作细节，而是"往哪走"的问题
- **可争论**：存在两种或以上合理路径，而非只有一个正确答案

**避免选择的议题**：
- 已有明确数据支撑的优化问题（如"降本5%"）
- 纯合规/法律问题（如"是否符合GDPR"）
- 个人绩效评估类议题

### Step 2: 角色分配

**红军（正方）**：
- 任务：捍卫现行战略/方案，证明其可行性
- 要求：必须真诚辩护，不能"故意放水"

**蓝军（反方）**：
- 任务：想尽一切办法否定红军，找出漏洞、模拟对手反击、提出危言耸听的警告
- 要求：必须"架着大炮轰"，不能点到为止

**裁判/决策者**：
- 任务：不提前表态，认真听取双方论点，最后拍板
- 要求：有最终决策权，且团队信任其公正性

**观察员**：
- 未参与辩论的中立人员，负责记录双方论点的逻辑漏洞和情绪走向

### Step 3: 辩论流程设计

**标准流程（推荐时长：2-4周，非连续）**：

| 阶段 | 时长 | 内容 |
|------|------|------|
| 战前准备 | 3-5天 | 双方各自调研、收集数据、构建论点 |
| 首轮交锋 | 半天 | 红军陈述方案 → 蓝军攻击 → 红军回应 |
| 模拟实践 | 3-5天 | 蓝军模拟竞争对手的反击策略，形成报告 |
| 深度推演 | 半天 | 双方就模拟结果进行第二轮交锋 |
| 外部输入 | 2-3天 | 引入外部专家/客户/合作伙伴的第三方视角 |
| 终局辩论 | 半天 | 双方做最后陈述，观察员提问 |
| 决策拍板 | 当天 | 决策者宣布决定，说明理由 |
| 复盘归档 | 1-2天 | 记录双方论点、决策理由、待验证假设 |

**快速流程（推荐时长：半天）**：
- 适用于时间紧迫但仍需压力测试的场景
- 30分钟：红军陈述
- 30分钟：蓝军攻击（必须至少提出3个致命漏洞）
- 30分钟：红军回应
- 15分钟：观察员提问
- 15分钟：决策者拍板

### Step 4: 规则设计

**必须遵守的规则**：
1. **对事不对人**：禁止人身攻击，所有批评针对"方案"而非"提案人"
2. **数据说话**：论点必须有数据或逻辑支撑，不能仅凭直觉
3. **角色分离**：辩论期间，双方不能"私下和解"或交换立场
4. **保密原则**：蓝军的某些攻击角度可能涉及敏感信息，需控制知悉范围
5. **结果导向**：无论蓝军是否"打赢"，最终目标是做出更好的决策

**禁止的行为**：
- 红军提前"贿赂"蓝军放水的行为
- 决策者提前表态导致一方士气受挫
- 将对抗结果与绩效考核直接挂钩

### Step 5: 决策与复盘

**决策者拍板时的关键问题**：
- 蓝军提出的最致命漏洞是什么？我们有应对方案吗？
- 如果蓝军模拟的竞争对手反击真的发生，我们能承受吗？
- 这个决策的"不可逆点"在哪里？过了哪个阶段就无法回头？
- 假设3年后证明这个决策是错的，最可能的原因是什么？

**复盘模板**：
```
议题：_________
红军核心论点：_________
蓝军核心攻击：_________
被采纳的蓝军建议：_________
被驳回的蓝军建议及理由：_________
决策：_________
关键假设（需后续验证）：_________
下次对抗可改进之处：_________
```

## B (Boundary) — 何时不适用

1. **执行层面的 operational 会议**：如周会、项目进度会，不需要红蓝对抗
2. **已达成共识的复盘**：复盘是为了学习，不是为了重新争论决策
3. **紧急危机**：需要快速决策，没有时间进行多轮对抗
4. **人际关系问题**：红蓝对抗解决的是"事"的问题，不是"人"的问题
5. **创意发散阶段**： brainstorming 阶段需要先"加法"再"减法"，对抗过早会扼杀创意
