# pbc-performance-contractor

PBC（Personal Business Commitment）绩效承诺设计与拆解：通过「战略解码→BSC平衡计分卡→KPI→个人PBC」四级分解，将组织目标转化为可执行、可衡量、可承诺的个人绩效契约。

## 触发条件

当用户需要设计绩效目标体系、制定个人绩效承诺、进行战略解码与目标分解、讨论PBC与KPI/OKR的区别、或需要PBC考核表模板时激活。

**关键词**：PBC / 个人绩效承诺 / 绩效目标设定 / 战略解码 / 目标分解 / WET / 绩效承诺 / 平衡计分卡 / BSC / KPI分解 / 个人业务承诺

## 使用说明

### 第一步：战略解码 — 从愿景到组织目标

将企业战略转化为全体员工可理解、可执行的行为目标。

**四维度解码（平衡计分卡）**：
1. **财务**：规模扩张、盈利性、投资回报、现金流
2. **客户**：客户满意度、市场份额、市场准入、商业环境
3. **内部流程**：质量、成本、服务、周期
4. **学习成长**：HR体系、干部队伍建设、IT建设、财务体系

**解码流程**：
1. 确定公司愿景、使命和战略
2. 导出公司级KPI（客户KPI、质量KPI、服务KPI、成本KPI、商业环境KPI）
3. 按BSC四维度分解到各部门
4. 形成部门年度工作重点 + 衡量标准（必须符合SMART原则）
5. 分解到个人PBC

**STOP检查点**：
- [ ] 战略目标是否转化为20%的关键指标（影响80%收益）？
- [ ] 各部门目标是否有明确的衡量标准，杜绝"大概""可能""尽量"等模糊词？
- [ ] 部门目标分解时，是否与所有相关部门进行了矩阵式对齐（打勾/打叉）？

### 第二步：PBC结构设计 — WET三要素

PBC包含三个核心部分，形成严密逻辑关系：

**W — 结果目标承诺（Win）**：
- 做什么？做到什么程度？
- 直接承接所在部门的组织绩效目标
- 一般应有衡量指标，说明做到什么程度或何时做完
- 权重通常占70%

**E — 执行措施承诺（Execute）**：
- 如何做？为达成绩效目标，员工与主管就方法和执行措施达成共识
- 是对工作执行过程的规范，引导员工用正确的方式把事做正确
- 执行目标一定与结果目标相对应
- 针对较重要的结果目标设置，非所有目标都需要

**T — 团队合作承诺（Team）**：
- 与谁做？需要谁的支持？
- 就交流、参与、理解和相互支持等方面进行承诺
- 主要是一种导向和牵引，强调对周边、流程上下游及上级的支持与配合

**PBC协议书两大部分**：
1. 关键指标（含组织指标、个人指标等）
2. 关键任务（年度重点工作，动态性指标，对KPI的补充完善，一般写5条左右）

**STOP检查点**：
- [ ] 结果目标是否有明确的衡量指标（量化或时间节点）？
- [ ] 执行措施是否与结果目标形成清晰对应关系？
- [ ] 团队目标是否体现了跨部门协作需求？

### 第三步：目标设定 — SMART标准

所有PBC目标必须遵循SMART原则：

| 原则 | 要求 | 反面示例 | 正确示例 |
|------|------|----------|----------|
| S Specific | 具体明确 | "提高客户满意度" | "通过收集客户群体反馈，提高客户满意度10%" |
| M Measurable | 可以衡量 | "准备客户分析材料" | "依据解决客户投诉行动计划，十天内解决相关投诉" |
| A Attainable | 可达到且有挑战性 | 目标过低或过高 | 保底/基本/挑战三级目标值 |
| R Relevant | 与工作职责相关 | 考核与岗位无关的事项 | 聚焦岗位职责和角色要求 |
| T Time-based | 有时间限定 | "后续完成""尽快" | "2018年12月完成""10月完成" |

**三级目标值设计**：
- **保底目标**：完成得0.8倍系数
- **基本目标**：完成得1.0倍系数
- **挑战目标**：完成得1.2倍系数

**STOP检查点**：
- [ ] 是否有使用模棱两可的词汇（可能、大概、尽量、后续）？
- [ ] 是否设定了保底/基本/挑战三级目标值？
- [ ] 权重分配是否合理（业务目标约70%，团队目标约30%）？

### 第四步：PBC运用与刷新机制

**年度流程**：
1. **10月-次年2月**：层层战略解码，形成目标及指标集
2. **2-4月**：完成全员PBC签署（书面承诺，杜绝人治）
3. **季度回顾**：每月/每季度经理协助员工考察PBC完成情况
4. **中期审视（4月/10月）**：PBC刷新，根据市场环境和公司现状调整指标
5. **年末评价**：直属经理打分，员工也对直属经理打分

**PBC刷新规则**：
- 指标落后或环境变化时可调整
- 调整必须有独立部门审核依据，不是随意调整
- 禁止年底集中调低指标

**评价流程（3级闭环管理）**：
1. 员工自评
2. 直接主管初评
3. 上级管理团队集体评议
4. 上上级结果审视（特别关注高低绩效和特殊人群）
5. 流程Owner行使建议否决权（确保横向一致性）

**STOP检查点**：
- [ ] PBC是否经过员工与主管共同商讨后签署？
- [ ] 是否建立了季度回顾和中期审视机制？
- [ ] 评价流程是否有集体评议和上级审视环节，防止个人偏见？

### 第五步：PBC vs KPI/OKR — 工具选择

| 维度 | PBC | KPI | OKR |
|------|-----|-----|-----|
| 本质 | 完整的绩效管理系统 | 系统的一部分 | 目标管理工具 |
| 关注点 | 结果+执行+团队+能力 | 阶段性结果 | 目标+关键结果 |
| 前瞻性 | 具有前瞻性 | 回顾阶段性成果 | 季度灵活调整 |
| 管理者角色 | 合作伙伴关系 | 上级对下级的评价 | 自下而上对齐 |
| 评价频率 | 季度/半年度/年度 | 多为年度 | 季度 |
| 末位淘汰 | 强制分布+末位淘汰 | 一般不强制 | 一般不强制 |
| 适用场景 | 管理基础好、岗位职责明确的中大型企业 | 结果导向明确的岗位 | 创新型、快速变化的环境 |

**华为PBC与IBM PBC的核心区别**：
- 华为：季度/半年度/年度考核，强制末位淘汰（后5%需改进），与奖金/配股/升迁全面挂钩
- IBM：年度考核为主，半年仅Review不打分，无强制末位淘汰，PBC 3分进入PIP

## 反模式警告

⚠️ **以下做法会导致PBC失效**：
1. 把PBC做成简单的任务监控（每天汇报进度），失去战略导向意义
2. 目标设定过于关注过程指标（日报、周报录入），忽视有效产出
3. 根据主管好恶打分，而非客观数据和事实
4. 为了挑员工毛病而考核，而非帮助员工成长
5. 把PBC当成克扣工资的工具，而非激发奋斗的手段
6. 只关注PBC表内事项，忽视岗位职责履行和超越职责的贡献
