# lean-process-reformer

## R — 原文 (Reading)

> "公司所有流程的改革一定要为客户服务，为客户服务产生价值，凡是绕了一大弯、不产生价值的流程都要砍掉。在行政服务这个非主干流程上可以实行流程责任制，包括流程各个节点的责任、权利和义务。"
>
> — 任正非, 第7章（简化行政管理）

---

## I — 方法论骨架 (Interpretation)

流程简化与责任制是一套区分"主干流程"和"非主干流程"、对后者进行激进简化甚至重构的方法。

核心逻辑：

1. **价值检验**：任何流程存在的唯一理由是"为客户服务产生价值"。绕弯、不产生价值、一线不支持的流程全部砍掉。

2. **二元区分**：主干流程（研发、销售、交付、财务合规等）强调严格遵从；非主干流程（行政服务、内部支持等）可以实行流程责任制。

3. **责任制替代审批**：在非主干流程上，不明确自上而下的审批链，而是设计每个节点的责任、权利、义务。责任人自主决策，出了问题背责。

4. **颗粒度控制**：行政服务以国家/区域为颗粒度做小循环，不建立跨国垂直全流程。本地小事不需要跨国家审批。

本质是用"责任"替代"审批"，用"小循环"替代"大流程"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 换灯泡写十几个邮件
- **问题**: 某代表处员工换个灯泡要写十几个邮件走流程，效率极低。
- **方法论的使用**: 砍掉不产生价值的审批流程，实行流程责任制，让本地责任人直接决策。
- **结论**: 行政管得越少，管得越好。
- **结果**: 推动华为行政体系全面流程简化，减少不必要的审批节点。

### 案例 2: 内服委员会流程改革
- **问题**: 行政服务流程臃肿，跨部门协调困难。
- **方法论的使用**: 成立内服委员会，由HR、财务、采购、审计等强者组成，设计非主干流程的责任制，明确各节点责权利。
- **结论**: 非主干流程不需要拉通全球全流程，以国家为颗粒度做小循环。
- **结果**: 行政服务流程大幅简化，响应速度提升。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 企业内部流程冗长，一个简单的行政/支持事项需要多层审批。
2. 一线员工抱怨"流程太复杂、办事太难"。
3. 需要区分哪些流程必须严格遵从、哪些可以放权。
4. 推行流程改革时，想砍掉不产生价值的环节但不知道怎么判断。
5. 非核心业务流程占据了管理人员大量时间，想转向责任制管理。

### 语言信号 (用户的话里出现这些就应激活)

- "流程太复杂了"
- "砍掉不产生价值的流程"
- "审批太多"
- "流程责任制"
- "非主干流程"
- "简化管理"
- "process simplification / too many approvals / lean process"

### 与相邻 skill 的区分

- 与 `ipd-change-management` 的区别: 后者是大型管理体系变革（如引入IPD），本 skill 是具体流程的简化与责任制设计。
- 与 `project-delay-prevention` 的区别: 后者聚焦研发项目防拖延，本 skill 聚焦通用流程精简。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **流程价值审计**
   - 完成标准: 列出目标流程的所有步骤，对每个步骤问"是否为客户服务产生价值？"，标记"有价值/无价值/不确定"。
   - 判停条件: 若该流程是合规/安全/财务主干流程，跳到步骤5（输出不适用建议）。

2. **砍掉无价值步骤**
   - 完成标准: 删除所有标记为"无价值"的步骤；对"不确定"的步骤，调研一线是否支持保留。

3. **设计流程责任制**
   - 完成标准: 对保留下来的步骤，明确每个节点的责任、权利、义务，形成《流程责任书》。
   - 判停条件: 若组织文化不支持"责任人自主决策+背责"（遇事必找上级），先进行文化铺垫或改为"简化审批链"。

4. **缩小颗粒度**
   - 完成标准: 检查流程是否跨越不必要的地理/组织边界，将跨国/跨区流程拆分为本地小循环。

5. **输出改革方案**
   - 完成标准: 输出《流程简化改革方案》，含原流程图、砍掉步骤清单、新责任制设计、小循环拆分说明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 合规/安全/财务等主干核心流程——这些流程强调严格遵从，不能随意简化。
- 需要严格审计追踪的敏感流程（如招投标、薪酬调整）。
- 组织文化极度集权、员工完全不习惯自主决策——需要先改变文化。
- 流程已经极简（3步以内）——没有简化空间。

### 作者在书中警告的失败模式

- **砍掉有价值流程**: 为砍而砍，把真正为客户服务的环节也砍掉。
- **主干流程也搞责任制**: 在研发、销售、财务合规等主干流程上放弃遵从，导致系统性风险。
- **急于废除老模式**: 新模式未立就砍旧模式，导致业务断档。

### 作者的盲点 / 时代局限

- 华为的"非主干流程"概念依赖于其成熟的主干流程体系（IPD、LTC、ITR）。很多企业连主干流程都没理清，谈"非主干"为时过早。
- "流程责任制"需要责任人具备足够的能力和判断力。能力不足的责任人会导致决策质量下降。

### 容易混淆的邻近方法论

- 与"流程自动化/RPA"的区别: 自动化是用技术加速流程，本 skill 是重构流程本身（砍掉或简化）。
- 与"敏捷/精益"的区别: 敏捷聚焦产品交付，本 skill 聚焦行政/支持类流程的精简。
