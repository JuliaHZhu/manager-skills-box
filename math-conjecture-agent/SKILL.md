# Math Conjecture Agent

## When to Use

当你有一个模糊的研究直觉/观察，想把它发展成可证明或可证伪的精确数学命题或理论猜想时激活。适用于：
- 从数据/现象中提炼形式化猜想
- 把直觉转化为精确的数学陈述
- 生成猜想的弱化/强化变体
- 评估猜想的可证性等级

不适用：纯计算题求解、已有标准答案的习题、不需要形式化的定性讨论。

## Trigger
- "我有个想法，能不能形式化一下"
- "从XX现象能提炼出什么命题"
- "这个观察能不能变成定理"
- "猜想生成"
- "formalize this intuition"
- "math conjecture"

## Workflow

### Step 1: 直觉解构
用户提供一个模糊的想法、观察或现象描述。Agent 先不急着形式化，而是追问：
- 这个现象成立的范围是什么？（定义域/前提条件）
- 反例可能长什么样？
- 你观察到的"模式"具体指什么？

### Step 2: 精确陈述生成
将直觉转化为至少 3 个不同严格程度的陈述：
1. **最强版**：最漂亮的猜想，但最难证明
2. **中等版**：去掉一些边角的版本，更可能成立
3. **最弱版**：核心直觉的最小可证版本

每个陈述用标准数学语言写出，并标注：
- 前提条件（Given / Assume）
- 结论（Then / We have）
- 量词范围（∀, ∃ 的范围）

### Step 3: 可证性评估
对每个版本给出一个快速评估：
- **可证性**（Provability）：高 / 中 / 低 / 开放
- **已知结果距离**：这个猜想与已有定理的差距有多大
- **建议证明策略**：构造性 / 反证法 / 归纳 / 归约到已知结果
- **关键障碍**：什么步骤最可能卡壳

### Step 4: 相关变体
生成 2-3 个相关猜想：
- 改变一个前提，看看结论是否还成立
- 反过来：如果结论成立，前提能弱化成什么
- 高维/连续/离散类比版本

## Output Format

```
=== 原始直觉 ===
[用户的原始描述]

=== 精确陈述 ===

猜想 A（最强）:
Given: ...
Then: ...
可证性: 低 | 障碍: ...

猜想 B（中等）:
Given: ...
Then: ...
可证性: 中 | 障碍: ...

猜想 C（最弱/核心）:
Given: ...
Then: ...
可证性: 高 | 策略: ...

=== 相关变体 ===
- 弱化前提版: ...
- 逆向版: ...
- 类比版: ...

=== 下一步建议 ===
1. 先证哪个版本
2. 需要补充什么背景知识
3. 可能的反例构造方向
```

## Example

用户："我观察到在很多优化问题里，局部最优好像经常就是全局最优，至少在我的数据集上是这样。"

Agent 输出：
- 追问：什么类型的优化问题？凸/非凸？离散/连续？数据分布有什么特性？
- 生成变体：从"所有局部最优都是全局最优"（最强，通常不成立）到"随机初始化梯度下降以高概率收敛到全局最优"（中等）到"在特定损失景观下，所有局部最优的函数值差距不超过 ε"（最弱，可证）
- 关联已知结果：凸优化、Morse 理论、神经正切核(NTK) regime

## Notes
- 永远先生成最弱可证版本作为安全网
- 如果用户提供了数据/代码，优先用具体例子验证直觉
- 与 `proof-outline-generator` 联动：选定猜想后直接生成证明大纲
