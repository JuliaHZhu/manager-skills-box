# 脆弱性诊断清单 (Fragility Diagnosis Checklist)

## R — 原文 (Reading)

> "请读者思考一下三元结构的定义，看看如何在各个领域中应用它。当你寻求秩序，你得到的不过是表面的秩序；而当你拥抱随机性，你却能把握秩序、掌控局面。"
>
> — 塔勒布, 第一卷序言

---

## I — 方法论骨架 (Interpretation)

脆弱性诊断清单是一个快速评估工具：通过10个问题，判断任何系统（个人、企业、投资、职业、关系）是否隐藏了脆弱性。

核心逻辑：脆弱性往往被"稳定"的表象掩盖。清单强迫你检查那些日常不会注意到的结构性弱点——单一依赖、预测依赖、不可恢复的失败模式、隐藏的尾部风险。

这不是一个"风险评估"（评估已知风险的概率和影响），而是一个"脆弱性扫描"（识别可能导致崩溃的结构性特征）。风险可以管理，脆弱性必须消除。

使用频率：重大决策前（换工作、大额投资、创业、进入新合作关系）必做。定期复查（如每季度）以检测新生成的脆弱性。

## A1 — 书中的应用 (Past Application)

### 案例 1: 银行系统的脆弱性
- **问题**: 为什么2008年银行系统如此脆弱？
- **方法论的使用**: 用清单扫描银行系统：单一依赖（住房抵押贷款）、预测依赖（房价永涨模型）、不可恢复（一旦挤兑即崩溃）、隐藏尾部（CDS等衍生品传染）、无切身利益（交易员有奖金无风险）。
- **结论**: 银行系统几乎命中了清单中的所有脆弱性指标。
- **结果**: 危机爆发，需要政府救助才能避免系统性崩溃。

### 案例 2: 个人职业脆弱性
- **问题**: 为什么"稳定工作"可能比"自由职业"更脆弱？
- **方法论的使用**: 扫描"稳定工作"：单一依赖（一个雇主）、预测依赖（需要行业持续景气）、不可恢复（失业后收入断崖）、隐藏尾部（年龄歧视、技术淘汰）。自由职业虽然不稳定，但多元客户结构反而降低了单一崩溃风险。
- **结论**: 表面上的"稳定"掩盖了结构性的脆弱。
- **结果**: 塔勒布倡导杠铃化的职业结构（安全保底+冒险探索）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 重大决策前（换工作、大额投资、创业、合作）想快速"体检"时
2. 感觉"一切正常"但隐隐不安时——清单能挖出隐藏脆弱
3. 定期复查个人/企业/投资组合的健康状况时
4. 评估一个新机会是否"看起来美好实则危险"时

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **明确诊断对象**
   - 完成标准: 确定用户要诊断的是什么（个人财务、职业、企业、投资、合作关系）

2. **运行10题脆弱性扫描**（每题"是"=1分，分数越高越脆弱）
   - [ ] 是否依赖单一收入来源/客户/技术/供应商？
   - [ ] 是否需要精确预测未来才能维持当前状态？
   - [ ] 失败/错误是否会导致不可逆的毁灭性后果？
   - [ ] 是否需要稳定/可控的外部环境才能运作？
   - [ ] 受冲击后，恢复时间是否随冲击增大而急剧延长？
   - [ ] 是否缺乏内置的纠错/失败/迭代机制？
   - [ ] 决策者是否不承担失败的个人后果？
   - [ ] 是否存在隐藏的尾部风险（低频但高损失）？
   - [ ] 系统的"稳定"是否来自外部干预/救助/补贴？
   - [ ] 是否禁止/惩罚小失败的发生？

3. **计算分数并评级**
   - 完成标准:
     - 0-2分 = 强韧/反脆弱 ✅
     - 3-5分 = 中等脆弱 ⚠️
     - 6-8分 = 高度脆弱 🚨
     - 9-10分 = 极度脆弱 💥（建议立即重构）

4. **给出改进建议**
   - 完成标准: 针对命中问题给出具体的反脆弱化建议（如多元化、增加冗余、引入试错机制、杠铃化等）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 日常琐事（如选择午餐）——清单 overhead 不值得
- 已经经历过完整风险评估的专业场景（如航空安全审查）——这些已有更专业的工具
- 处于紧急危机中——此时需要行动，不是诊断

### 作者在书中警告的失败模式

- **假安全感**: 得分低不代表绝对安全——清单只覆盖已知脆弱性指标，未知的黑天鹅始终存在
- **过度诊断**: 频繁使用清单导致"分析瘫痪"——诊断是为了行动，不是为了完美
- **指标游戏**: 为了提高分数而做表面调整（如形式上"多元化"但实际上高度相关）

### 作者的盲点 / 时代局限

- 清单基于《反脆弱》的特定视角，可能遗漏其他风险框架（如网络安全、环境风险）中的重要指标
- 10题的权重相同，但实际上某些指标（如"单一依赖"）可能比其他的致命性更高

### 容易混淆的邻近方法论

- 与"SWOT分析"的区别: SWOT同时看优劣势，诊断清单只看脆弱性（劣势中最危险的部分）
- 与"风险矩阵"的区别: 风险矩阵评估"概率×影响"，诊断清单评估"结构性脆弱特征"（不论概率）
