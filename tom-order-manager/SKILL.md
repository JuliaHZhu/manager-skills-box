# TOM全面订单管理模型

## R — 原文 (Reading)

> TOM模型，即全面订单管理模型，顾名思义，它主要是关注企业在订单履行方面的管理。TOM模型涵盖了从客户的需求到订单履行的整个过程，主要包括资源管理、需求管理、制造管理和可供应能力管理这四个模块。TOM模型的特点就在于它是一个计算机化的、有规则体系的、严格控制的计划流程。流程、规则和数据是TOM模型中不可或缺的部分，其中，规则是其非常重要的一个部分，也正是支持企业运作的部分。
>
> — 华为计划手册, 4.1 TOM模型

> 资源合理化流程是一个月度流程（S&OP也是一个月度流程），是根据制定好的一系列业务规则，考虑资源约束的状况，对资源进行合理分配的流程。通过资源合理化流程，不仅在资源有限的情况下，可以保证首先满足最重要、最紧急的需求，而不是最近的或者是叫得最响的需求。
>
> — 华为计划手册, 资源管理

## I — 方法论骨架 (Interpretation)

TOM（Total Order Management）是一个四方阵闭环计划模型，核心目标是"所有承诺一言九鼎"。

**四方阵闭环**:
1. **资源管理**（第一方阵）: 月度S&OP流程，输入无约束需求预测+资源状况+业务规则，输出粗可行的发货计划（Capable of Shipping Plan）
2. **需求管理**（第二方阵）: 将高层计划通过产品组合预测分解，与客户层次、需求类型关联，输出按优先级排序的需求
3. **制造管理**（第三方阵）: 在Item层面锁定需求与供应，考虑工厂执行规则（最优批量、拉入推出），输出执行信号
4. **可供应能力管理**（第四方阵）: 实时ATP计算与调配，订单排产、状态查询、重排程，输出更新的可供应能力反馈回第一方阵

**业务规则体系**是TOM的灵魂：
- 管理层指令: 产品最大/最小量规则
- 需求类型优先级: 已签订单 > 客户预留 > 预测
- 产品策略: 最小保护量 > 全力支持 > 公平分配
- 区域策略: 同产品策略逻辑
- 客户策略: 分层服务（第一层客户可预留+短提前期）

## A1 — 书中的应用 (Past Application)

### 案例 1: 华为实施ERP时的ATP教训（1998年）
- **问题**: 华为电气实施ERP时使用了ATP功能，但两个月后取消
- **方法论的使用**（反面教材）:
  - 变革准备不够，业务运作理念不系统："ATP检查似乎是生产计划要求市场做的事，但却没有得到高层的理解和支持"
  - 无S&OP概念："主生产计划也没有起到作用"
  - ATP检查内容太多、柔性太差、需求预测偏差大
- **结论**: TOM/ATP的成功需要规则、流程、数据、组织准备四要素齐全
- **结果**: ATP功能退下，待ISC项目推行集成ERP后才可能重新启用

### 案例 2: 资源合理化中的客户分层
- **问题**: 需求总是大于供应，如何公平合理地分配资源？
- **方法论的使用**: 
  - 客户分四层：公司级客户/战略客户/分销商/OEM
  - 第一层客户可预留+短提前期；预留有取消窗口
  - 产品策略三层：最小保护量（维持市场）> 全力支持（高利润/战略/新产品）> 公平分配（默认）
- **结论**: 资源分配必须在计划阶段而非执行阶段进行
- **结果**: 形成标准化的业务规则流程

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 企业计划体系混乱，销售、生产、采购各自为政，需要建立统一的计划流程
2. 经常对客户承诺后无法兑现，需要提升订单履行的可信度
3. 需求大于供应成为常态，需要设计资源分配的业务规则
4. 导入ERP/APS系统前，需要理清业务流程和规则体系
5. 客户投诉交货不及时或分批发货混乱，需要优化订单可视性和重排程机制

### 语言信号 (用户的话里出现这些就应激活)

### 与相邻 skill 的区分

- 与 `bottleneck-material-allocator` 的区别: 本 skill 是全局计划框架设计，bottleneck-material-allocator 是其中ATP计算和瓶颈分配的操作层
- 与 `production-control-operator` 的区别: production-control-operator 是车间执行层，本 skill 是端到端计划体系
- 与 `inventory-health-diagnoser` 的区别: 本 skill 不处理库存诊断，而是通过规则管理库存策略（BTF/安全库存等）

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **评估当前计划体系成熟度**
   - 完成标准: 识别是否存在以下缺失
   - 检查清单:
     - [ ] 是否有月度S&OP或类似的高层资源匹配会议？
     - [ ] 是否有无约束的需求预测？
     - [ ] 需求、供应、规则、数据四要素是否齐全？
     - [ ] 订单承诺是否有ATP机制支撑？
     - [ ] 承诺后是否能跟踪履行状态？

2. **设计业务规则体系**
   - 完成标准: 输出完整的业务规则文档
   - 规则模块:
     - **管理层指令**: 各产品最大/最小量规则（生命周期管理）
     - **需求类型优先级**: 已签订单（退货/样品/其他）> 未签订单（客户预留/一般预测）
     - **产品策略**: 最小保护量/全力支持/公平分配
     - **区域策略**: 同产品策略逻辑
     - **客户策略**: 分层预留与提前期差异

3. **构建四方阵流程**
   - 完成标准: 输出四方阵流程图和接口定义
   - 四方阵接口:
     | 方阵 | 输入 | 输出 | 频次 |
     |---|---|---|---|
     | 资源管理 | 无约束预测+资源状况+规则 | 粗可行发货计划 | 月度 |
     | 需求管理 | 粗可行计划+客户数据+产品层次 | 优先级排序的需求 | 按需求更新 |
     | 制造管理 | 排序需求+供应可视性+工厂规则 | 执行信号+额外资源 | 日到周 |
     | 可供应能力 | 额外资源+新订单 | ATP+订单状态+更新能力 | 实时 |

4. **设计需求管理中的产品组合预测分解**
   - 完成标准: 建立产品层次结构和计划百分比计算机制
   - 关键动作:
     - 定义产品层次（最多8层，可销售器件只能出现一次）
     - 收集历史发货、未执行订单、客户预留、预测，赋权重计算组合预测百分比
     - 将高层计划分解到Item层次，扣除可用库存后传递净需求

5. **设计可供应能力管理（ATP）机制**
   - 完成标准: 输出ATP计算规则和调配规则
   - ATP计算: 当前库存 + 计划供应 - 已确认需求 = 可承诺量
   - ATP整合规则: 公用资源约束时，从细节层向上整合到产品族，按管理指令分配
   - ATP调配规则: 高优先级客户可从低优先级客户获取ATP（用完自己份额后）

6. **制定实施路线图**
   - 完成标准: 分阶段实施计划，避免华为1998年ATP失败的覆辙
   - 阶段建议:
     - 阶段1: 建立无约束预测和基础数据质量
     - 阶段2: 建立月度S&OP/资源合理化流程
     - 阶段3: 引入需求管理和产品组合预测分解
     - 阶段4: 连接制造管理和工厂执行规则
     - 阶段5: 上线ATP和客户订单查询

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯贸易流通企业无制造环节（TOM的制造管理方阵不适用）
- 已经拥有成熟IBP/APS系统且运行良好，仅需局部参数调整
- 企业规模极小（<50人），计划可由一两个人口头协调

### 作者在书中警告的失败模式

- 变革准备不足就上系统："ATP检查似乎是生产计划要求市场做的事，但却没有得到高层的理解和支持"
- 缺乏S&OP概念："计划部门总是小心翼翼地将收集到的市场预测...加工成采购和制造指令，总是埋怨预测不准，很少考虑供需和产能平衡"
- 规则缺失导致执行混乱：没有业务规则时，"最近的或者是叫得最响的需求"会抢占资源
- ATP检查内容太多、结果太乱："当其中有一个子项检查不能通过时，整个栏目都受影响...让人很难从中找到具体原因"

### 作者的盲点 / 时代局限

- TOM模型由IBM顾问在ISC项目关注阶段引入（2000年前后），基于传统MRPII/ERP架构
- 现代云原生供应链系统（如SAP IBP、Kinaxis、o9）已实现实时协同和AI优化，但业务规则逻辑仍适用
- 未涉及跨境电商、DTC等新兴业态的订单履行特征

### 容易混淆的邻近方法论

- TOM vs ISC: ISC是华为整体供应链变革项目，TOM是其中订单履行方面的计划模型；ISC范围远大于TOM
- TOM vs MRP/MPS: MRP/MPS是TOM第三方阵（制造管理）中的工具，TOM是涵盖资源/需求/制造/可供应能力的完整框架
- S&OP vs 资源合理化: 资源合理化流程相当于S&OP，但TOM将其嵌入更大的四方阵闭环中
