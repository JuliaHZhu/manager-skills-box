# 战略解码：从SP到BP分解

## R — 原文 (Reading)

> 战略解码的核心原则是，价值创造决定价值分配。整个战略解码过程是，从公司的战略洞察到战略分解，到指标体系，再到确定各个组织的KPI，然后到个人PBC。
>
> — 华为战略管理实践, 第18章

> 战略是结构效率，执行是运营效率。结构效率大于运营效率，但是没有运营做支撑，战略就无法有效落地。
>
> — 华为战略管理实践, 第18章

---

## I — 方法论骨架 (Interpretation)

战略解码是将"战略意图"转化为"组织行为"的翻译过程。它不是简单的目标拆解，而是**价值创造逻辑的层层传递**——先识别哪些行为真正创造价值，再把这些行为转化为可衡量的指标，最终落到个人承诺。

核心逻辑链：
**战略洞察 → 战略方向 → 战略机会点 → 业务设计 → 战略里程碑（SP侧）**
**↓ 解码 ↓**
**机会点到订货目标 → 策略和行动计划 → 关键财务指标 → 预算 → 组织KPI → 个人PBC（BP侧）**

关键原则：
1. **垂直一致性** — 公司→体系→部门→岗位，PBC逐级承接战略目标
2. **水平一致性** — 以端到端业务流程为基础，建立部门间的连带责任和协作关系
3. **价值创造决定价值分配** — 不是"自上而下压指标"，而是"识别价值创造行为→设计KPI→分解到个人"

华为的做法：先建立KPI Pool（指标池），每年根据战略调整和客户需求变化刷新，再由战略解码团队（HR+战略规划+业务部门）设计各部门的KPI集合。

## A1 — 书中的应用 (Past Application)

### 案例 1: 华为无线业务的战略解码
- **问题**: 无线业务如何从战略规划落地为可执行的年度目标和组织行动？
- **方法论的使用**: SP侧明确无线作为"海量市场+战略控制点（专利+客户关系）"的定位；BP侧将机会点分解为订货目标、区域客户突破计划、研发投入预算；组织KPI围绕"客户选择正确率""专利产出""客户满意度"设计；个人PBC落到欧洲区无线行销经理的"锁定6个重点客户并全部突破"
- **结论**: 战略解码使无线业务从1998年起步发展为华为的现金流牛
- **结果**: 无线成为华为最成功的事业部之一

### 案例 2: 欧洲区无线行销经理的PBC设计
- **问题**: 如何将"突破欧洲市场"的战略目标分解为个人的可衡量承诺？
- **方法论的使用**: 核心考核指标不是销售额，而是"客户选择+客户突破"——选择6个重点客户并全部突破。如果只突破4个，即使销售额达标，考核结果也是不好的，因为"客户选择出了问题"
- **结论**: 价值创造行为（选择正确的客户并突破）决定了KPI设计，而非单纯的财务结果
- **结果**: 形成了"选择6个、突破6个"的刚性执行文化

### 案例 3: 华为终端业务的战略解码
- **问题**: 终端业务（To C）与运营商业务（To B）截然不同，如何将战略解码方法论适配到终端？
- **方法论的使用**: 引入BLM和BEM（战略执行管理）方法论，用平衡计分卡从四个维度解码；强调"以客户为中心的流程和管理体系"在2B和2C领域都适用
- **结论**: 战略解码的核心逻辑（价值创造→价值分配）具有跨业务通用性
- **结果**: 终端业务成功复制了运营商业务的执行力

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 公司制定了3年战略规划，但中层管理者不知道如何承接时
2. 年度OKR/KPI设计时，发现各部门目标互相冲突或与公司战略脱节时
3. 战略很清晰但执行总是不到位，需要找到从"意图"到"行动"的断裂点时
4. 新业务线刚成立，需要从零建立目标分解体系时
5. 绩效考核改革时，需要将"价值创造"逻辑嵌入考核体系时

### 语言信号 (用户的话里出现这些就应激活)

- "战略很虚，怎么落地？"
- "年度目标怎么定？"
- "KPI怎么设计才合理？"
- "部门目标互相打架怎么办？"
- "战略解码 / 目标分解 / SP到BP / 组织KPI / 个人PBC"
- "strategy decoding / objective alignment / KPI design / strategy execution"

### 与相邻 skill 的区分

- 与 `blm-strategic-planning` 的区别: BLM负责"制定战略"，本 skill 负责"把战略变成可执行的行动"
- 与 `dste-strategy-execution` 的区别: DSTE是宏观流程框架（SP→BP→监控），本 skill 聚焦于"解码"这一关键环节的具体方法
- 与 `stretch-goals-capability-building` 的区别: 本 skill 解决"怎么分解"，高目标 skill 解决"目标定多高、为什么定高"

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **明确战略输入**
   - 完成标准: 清晰陈述公司的战略意图、战略机会点和业务设计（若用户未提供，先引导补充）
   - 判停条件: 若用户连"我们要去哪里"都不清楚，先引导其用BLM或五看明确战略，再谈解码

2. **设计价值创造链条**
   - 完成标准: 识别出支撑战略目标的关键价值创造行为（3-5个），并说明为什么这些行为创造价值
   - 步骤:
     a. 列出所有可能影响战略目标达成的业务行为
     b. 筛选出"对价值驱动因素有直接杠杆作用"的核心行为
     c. 按价值链顺序排列这些行为

3. **构建KPI Pool**
   - 完成标准: 为每个价值创造行为设计1-2个可量化指标，形成指标池
   - 注意: 区分"结果指标"（滞后）和"过程指标"（领先），优先选择过程指标

4. **分解到组织和个人**
   - 完成标准: 按垂直一致性（逐级承接）和水平一致性（流程互锁）原则，将KPI分解为组织KPI和个人PBC
   - 输出: 一张从公司战略到个人PBC的解码地图

5. **一致性校验**
   - 完成标准: 检查是否存在"上下不一致"或"左右不对齐"的问题，提出3个校验问题让用户确认

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 没有明确战略目标的纯绩效考核设计 — 先明确战略再谈解码
- 初创公司尚未找到产品市场契合点（PMF）前的目标分解 — PMF前战略方向可能快速调整，过早固化KPI有害
- 个人OKR设定但无组织战略上下文 — 个人目标需要承接组织目标，孤立的个人OKR容易变成"自嗨"
- 只有财务目标（如"今年营收增长30%"）但没有战略行动路径 — 先补充战略内容

### 作者在书中警告的失败模式

- **战略规划很虚**：如果只写战略洞察和方向而不解码到KPI和PBC，战略就是虚的
- **延长线思维**：BP不是SP的线性延长，而是基于机会点的重新设计
- **忽视流程互锁**：只保证"上下同欲"而不保证"左右对齐"，会导致部门各自为政
- **KPI僵化**：KPI Pool必须每年刷新，战略调整和客户需求变化都要求指标更新

### 作者的盲点 / 时代局限

- 华为有400多个业务单元和完善的流程体系，中小企业可能没有足够的管理带宽来维护复杂的KPI Pool
- 强调"价值创造决定价值分配"，但在创意型、探索型工作中，价值创造难以事前量化

### 容易混淆的邻近方法论

- 与OKR: OKR是目标管理工具，战略解码是目标生成逻辑；OKR关注"做什么"，战略解码关注"为什么这么做能创造价值"
- 与平衡计分卡: 平衡计分卡是解码的维度框架（财务/客户/内部/学习），战略解码是内容生成方法
