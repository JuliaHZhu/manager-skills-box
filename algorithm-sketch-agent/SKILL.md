# Algorithm Sketch Agent

## When to Use

当你有一个算法想法，需要从自然语言描述推进到伪代码、复杂度分析和边界情况时激活。适用于：
- 把解决问题的直觉转化为结构化算法
- 快速估算时间/空间复杂度
- 生成反例和边界测试
- 识别算法瓶颈和优化方向

不适用：纯代码实现（已有 copilot）、不需要分析的小脚本、完全标准的经典算法（直接查书即可）。

## Trigger
- "我想设计一个算法..."
- "怎么高效地解决XX问题"
- "这个思路复杂度是多少"
- "算法草图"
- "sketch an algorithm"
- "algo design"

## Workflow

### Step 1: 问题精确定义
把用户的自然语言描述转化为算法问题的标准五元组：
- **输入**（Input）：数据类型、规模、约束
- **输出**（Output）：期望返回什么
- **目标**（Objective）：优化什么（时间/空间/近似比/正确率）
- **约束**（Constraints）：硬性限制（在线/离线、内存限制、不允许排序等）
- **模型**（Model）：计算模型假设（RAM/比较模型/Oracle访问等）

### Step 2: 算法草图
输出三层描述：
1. **高层直觉**（1-2句话）：这个算法最核心的 trick 是什么
2. **结构化伪代码**：用类 Python 伪代码，保留关键数据结构操作
3. **正确性不变式**：循环不变式或递归不变式，说明为什么算法正确

### Step 3: 复杂度分析
给出三层分析：
- **最坏情况**（Worst-case）：Big-O 上界
- **最好情况**（Best-case）：何时达到
- **平均/摊还**（Amortized/Average）：如果适用

同时标注隐藏的常数因子（比如哈希表查找的 O(1) 实际代价）。

### Step 4: 边界与反例
- 生成 3 个边界输入：最小输入、最大输入、病态输入
- 构造 1 个反例（如果算法是近似的或启发式的）
- 指出什么条件下算法会退化（degenerate）

### Step 5: 优化空间
列出 2-3 个可能的改进方向：
- 数据结构替换（如数组→线段树）
- 近似策略（如果精确解太贵）
- 并行化/分布式可能性

## Example

用户："我想找出两个大集合的交集，但内存不够加载整个集合。"

Agent：
- 问题定义：Input 是两个流式集合 A,B，|A|=n, |B|=m；Constraint 是内存 M << n+m
- 草图：外部排序 + 双指针（如果可排序）；或 Bloom filter + 验证；或 Hash 分桶外排
- 复杂度：外部排序 O((n+m) log_M (n+m)) I/O；Bloom filter O(n+m) 时间，但有假阳性
- 边界：一个集合完全为空；两个集合完全相同；数据分布极度倾斜

## Notes
- 伪代码优先于真实代码，重点在思路而非语法
- 如果用户没有指定计算模型，默认 RAM 模型
- 与 `math-conjecture-agent` 联动：算法正确性本身可以作为一个猜想进行形式化分析
- 与 `proof-outline-generator` 联动：算法的正确性证明可以生成证明大纲
