# demand-supply-balancer

## Metadata

- **Author**: Cangjie distillation from 《华为管理手册（5版）——计划手册》
- **Trigger**: S&OP / 销售与运作计划 / 供产销评审 / 需求评审 / 供需平衡 / 需求管理 / 无约束预测 / 平滑波动

## Purpose
通过S&OP（销售与运作计划）机制和系统的需求评审方法论，帮助用户实现市场需求与供应能力的动态平衡，重点解决需求计划制定、供需评审、需求波动平滑和跨部门协同问题。

## When to Use
- 需要建立或优化月度/季度供需评审机制时
- 市场需求波动大，生产/采购抱怨需求不稳定时
- 需要制定无约束市场需求计划并转化为可执行发货计划时
- 研发新产品需求冲击量产计划时
- 内部需求（备件/维修/研发）管理混乱时
- 需要建立从战略到日常运作的需求管理闭环时

## STOP Checkpoints
- [ ] 市场提供的预测是否包含波动上下限？
- [ ] 供应方是否已识别所有关键约束资源？
- [ ] 本次会议是否有明确的可执行发货计划输出？

## Inputs
- 销售预测、在谈项目、合同剩余、历史发货数据
- 产能数据、关键物料供应能力、瓶颈资源清单
- 研发项目计划、内部需求申请
- 库存水平、安全库存策略

## Outputs
- 无约束市场需求计划（含波动范围）
- 可执行发货计划
- 供需平衡决策记录
- 关键约束资源应对方案
- 研发/内部需求评审结论

## Procedure

### 阶段一：市场需求计划制定与评审
1. **销售预测制定**：信息收集与分析 → 专家预测+统计分析 → 预测评审决策 → 输出12个月分产品销售计划。
2. **无约束需求计划**：
   - 短期（3-5个月）：小合同剩余 + 大合同剩余 + 即将签单重大项目 + 销售预测（不含即将签单项目）。
   - 长期：根据销售和发货比例确定。
3. **需求计划评审**：
   - 市场计划提供无约束需求及波动上下限，**不评审需求可信度**（由市场负责）。
   - 评审重点是需求变动信息通报和供需沟通协调。

### 阶段二：S&OP供产销评审会
1. **会议结构**：
   - **预备会**：需求协调者（市场计划）+ 需求管理者（生产/采购）参加，作出供需平衡决策、制定方案、识别分歧。
   - **正式S&OP会**：高层领导参加，基于预备会方案进行决策。
2. **议程**：
   - 上期计划执行情况分析（生产计划）
   - 本期无约束市场需求介绍（市场计划，含波动上下限）
   - 本期供应能力介绍（采购/制造，含关键物料和产能瓶颈）
   - 可执行发货计划评审（综合平衡）
3. **评审规则**：
   - **供大于求**：以无约束预测作为可执行发货计划，启用安全库存调节。
   - **供不应求**：
     - 安全库存减小或归零，全部库存支援前线；
     - 对客户订单排序，确定必须满足量；
     - 按瓶颈资源最大量排产，市场和采购两边承诺；
     - 平滑需求波动（劈山填海、安全库存）。
4. **S&OP预备会详细议程**：
   - 绩效审视 → 需求审视 → 新产品审视 → 假设与风险分析 → 约束资源审视 → 产能和采购量建议 → 业务影响识别 → 制定方案 → 准备建议 → 制定正式会议议程。

### 阶段三：研发新产品需求评审
1. **专用/公用物料区分**：
   - 所有组织均为公用 → 公用物料；
   - 某组织专用，其他组织公用 → 该组织仍视为公用；
   - 某组织专用，其他组织也为其他新产品专用 → 该组织视为专用。
2. **不完整BOM阶段**：研发以内部需求形式提器件/单板需求，生产计划评审波动性、可供应能力、对量产冲击。
3. **完整BOM阶段**：
   - 检查预测录入方式和项目合理性；
   - 例行检查计划属性和计划百分比；
   - 异常集中/大需求量沟通分期分批；
   - 严格检查版本切换/小版本升级比例；
   - 长单/储备/停产器件谨慎处理。
4. **常见问题预防**：
   - 内部需求及时核销（需求变化立即通知）；
   - 防止漏报/不报（研发使用量产物料必须通知生产计划）；
   - 版本切换/过渡版本严格控制。

### 阶段四：其他内部需求评审
1. **需求部门**：产品线项目管理处（研发/自制设备）、维护事业部（维护/扩容）、中央备件部（备品备件）。
2. **提交规范**：不能包含ATO/PTO/POC/PH项目（机柜/插框/电缆除外），必须分解到P/SI/AI层级。
3. **评审要素**：计划波动性、物料ATP能力、低版本半成品ATP、需求总量。
4. **特殊处理**：
   - 研发环境需求：常涉及试制/研发状态产品，需研发计划共同参与。
   - 中央备件需求：版本多、低版本需求多，不能满足的需达成一致。
   - 维护事业部需求：量小，重点审核零星领料。
5. **组织间内部需求**：以内部订单形式发放核销，关注项目属性准确性、核销及时性、需求波动性，必须有正式文件依据。

## Key Principles
- S&OP是连接战略与日常运作的桥梁，不是简单的会议，而是决策流程。
- 无约束预测反映真实市场机会，与产能对比可知"失去了多大的市场"。
- 需求管理的三个层次：业务需求（最高）→ 绩效需求（中间）→ 学习需求（最低）。
- 对准业务需求是计划工作最大的"势能"，成功借势可"不战而屈人之兵"。
- 研发与生产计划不是独立体系，必须经常沟通，"计划先转产，产品后转产"。

## Failure Modes
| 症状 | 可能原因 | 对策 |
|------|----------|------|
| 供产销会流于形式，供需仍失衡 | 会议目标不清晰/未准备无约束需求和供应能力数据/缺乏决策规则 | 明确会议目标是供需平衡；强制模板化输入；建立供大于求/供不应求的决策规则 |
| 研发需求频繁冲击量产 | 研发计划与生产计划脱节/内部需求未及时核销/公用物料定义不清 | 建立定期沟通机制；规范内部需求核销流程；明确专用/公用物料区分规则 |
| 需求预测总是不准 | 只盯学习需求（员工要什么课）/未对准业务需求 | 从业务目标出发反向推导绩效需求和能力需求；放弃无效的需求调查表 |
| 内部需求造成大量死料 | 需求编码错误/评审未检查项目用途和资金额/无闭环核销 | 评审时检查编码、用途、资金额；建立核销机制；设置监控点 |
