# Proof Outline Generator

## When to Use

当你有一个待证明的命题（数学定理、算法正确性、博弈论结论等），需要系统性地组织证明思路时激活。适用于：
- 从零开始规划一个证明的结构
- 卡壳时寻找新的证明路径
- 把自然语言论证转化为严谨的证明步骤
- 评估不同证明策略的难易度

不适用：纯计算验证、已有标准证明的教科书习题、不需要证明的定性结论。

## Trigger
- "怎么证明这个"
- "给我个证明思路"
- "证明大纲"
- "proof outline"
- "how to prove"
- "stuck on proof"

## Workflow

### Step 1: 命题解析
将待证命题拆分为：
- **前提（Hypotheses）**：所有给定条件，编号 H1, H2, ...
- **结论（Conclusion）**：需要证明的目标，编号 C
- **隐藏假设**：命题依赖但未明说的数学结构（如度量空间完备性、选择公理等）

### Step 2: 证明策略树
生成至少 3 条不同的证明路径，形成策略树：

```
目标 C
├── 路径 A: 直接构造法
│   ├── 子目标 A1: 构造满足条件的对象 X
│   └── 子目标 A2: 验证 X 满足所有约束
├── 路径 B: 反证法
│   ├── 子目标 B1: 假设 ¬C，推出矛盾
│   └── 子目标 B2: 矛盾必须与某个已知定理/公理冲突
└── 路径 C: 归约法
    ├── 子目标 C1: 将 C 归约到已知定理 T
    └── 子目标 C2: 验证前提满足 T 的应用条件
```

每条路径标注：
- **预估难度**：高/中/低
- **需要的工具**：什么引理/定理/技术
- **风险点**：哪一步最容易失败

### Step 3: 引理清单
列出证明过程中可能需要的前置引理：
- **已知引理**：标准结果，直接引用
- **需证引理**：需要自己证明的中间结果，评估其独立价值
- **辅助定义**：证明中需要引入的新概念或记号

### Step 4: 详细大纲
对选定的一条路径（默认推荐难度最低的那条），展开为详细的步骤大纲：

每一步包含：
- **步骤编号**
- **断言**：这一步要证明什么
- **理由**：基于什么（定义/假设/前一步/已知定理）
- **状态**：从当前已知能推出什么新结论

## Output Format

```
=== 命题解析 ===
Hypotheses:
  H1: ...
  H2: ...
Hidden assumptions: ...
Conclusion: C = ...

=== 证明策略树 ===

路径 A - [构造法] - 难度: 中
  子目标: ...
  工具: ...
  风险: ...

路径 B - [反证法] - 难度: 低 ⭐推荐
  子目标: ...
  工具: ...
  风险: ...

路径 C - [归约法] - 难度: 高
  子目标: ...
  工具: ...
  风险: ...

=== 引理清单 ===
已知:
  L1: ... (引用来源)
需证:
  L2: ... (价值: 可能独立成引理)
辅助定义:
  D1: ...

=== 详细大纲（路径 B） ===
Step 1: [断言] ...
        [理由] 由 H1 和定义 D1
        [状态] 已知: H1,H2,D1 ⊢ P1

Step 2: [断言] ...
        [理由] 反设 ¬C，结合 P1
        [状态] 已知: ...,¬C ⊢ P2

...

Step N: [断言] 矛盾！
        [理由] P_{N-1} 与已知定理 L1 冲突
        [状态] ¬C 不成立，故 C 成立 ∎

=== 下一步 ===
1. 先证哪个引理
2. 需要查阅什么文献
3. 如果路径 B 失败，回退到路径 A 的切换点在哪
```

## Example

用户："证明：在一个有限策略集的两人零和博弈中，如果允许混合策略，则一定存在纳什均衡。"

Agent：
- 解析：H1=有限策略集，H2=两人零和，C=混合策略纳什均衡存在
- 策略树：
  - 路径 A（直接构造）：构造线性规划对偶，难度中
  - 路径 B（不动点定理）：用 Brouwer 不动点定理，难度低（经典）
  - 路径 C（学习算法收敛）：用 no-regret learning 证明收敛到均衡，难度高
- 推荐路径 B，展开为：定义混合策略单纯形 → 构造最佳反应映射 → 验证连续性 → 应用 Brouwer → 验证不动点就是纳什均衡

## Notes
- 优先推荐难度最低的路径，但保留更漂亮的路径作为备选
- 如果命题本身就是开放的（open problem），直接说明，不硬凑证明
- 与 `math-conjecture-agent` 联动：证明大纲可以反向提示猜想的弱化版本
- 与 `autoformalization-helper` 联动：大纲的每一步可以映射到形式化语言
