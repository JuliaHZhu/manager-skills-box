# bom-eco-guardian

## Metadata
- **Version**: 1.0.0
- **Author**: Cangjie distillation from 《华为管理手册（5版）——计划手册》
- **Trigger**: BOM管理 / 物料清单 / 工程变更 / ECO / 项目模板 / 产品结构树 / 计划百分比 / 清单版本

## Purpose
指导用户管理BOM工程数据，包括产品结构树设计、项目模板选择、BOM清单维护、ECO工程更改控制、计划百分比维护，确保计划基础数据的准确性。

## When to Use
- 新产品开发需要建立BOM结构时
- 需要申请项目编码或定义项目模板时
- 发生工程变更（ECO）需要修改BOM时
- 计划百分比需要调整时
- BOM数据错误导致计划结果偏差时
- 需要理解不同项目模板（ATO/PTO/PH等）的用法时

## STOP Checkpoints
- [ ] ECO实施前是否已评估对库存和在途订单的影响？
- [ ] 计划百分比调整是否已参考历史配置统计和未来预测？
- [ ] 新项目模板选择是否符合业务场景（销售/装配/发货方式）？

## Inputs
- 产品总体设计方案、功能划分
- 客户选配需求、商务发货方式
- 历史要货配置统计、版本切换信息
- 现有BOM清单、项目编码规则

## Outputs
- 产品结构树
- 项目编码申请、项目模板定义
- BOM清单（标准/模型/可选类/计划）
- ECO工程更改单
- 计划百分比调整方案

## Procedure

### 阶段一：产品结构树设计
1. **定义**：描述产品物料组成和文件组成的层次结构树，是产品总体设计完成的标志之一。
2. **原则**：
   - 每个独立"整机产品"对应一个结构树。
   - 反映自制项目和关键采购物料，非关键采购物料不需反映。
   - PTO/ATO/POC/AOC项目都应展开到下一层。
   - 成品板展开到下一层；制成板含软件/结构件也需展开。
   - 借用其他产品的项目不展开。
3. **评审**：PDT开发项目组、产品数据小组、报价、成套、工艺、试制、计划等部门参与评审。
4. **维护**：归档后更改受控，需相关环节审核、数据批准人批准。

### 阶段二：项目模板选择
| 模板 | 代码 | 使用场景 | 库存 | 清单 |
|------|------|----------|------|------|
| 采购项目 | P | 直接从供应商购买 | 有 | 无 |
| 供应项目 | SI | 大量领料，不按单领料 | 有 | 无 |
| ATO项目 | AI | 构成固定，按MRP装配，可销售 | 有 | 标准 |
| 虚拟项目 | PH | 装配过程在制品，自动分解 | 一般无 | 标准 |
| ATO模型 | ATO | 客户可选部件，商务选配 | 无（模型） | 模型 |
| AOC | AOC | 可选组件集合，参与下级装配 | 无 | 可选类 |
| 成品 | FG | 最终产品，固定构成 | 有 | 标准 |
| PTO模型 | PTO | 含装配+直接发货物料混合体 | 无（模型） | 模型 |
| POC | POC | 直接发货项目集合，商务挑选 | 无 | 可选类 |
| KIT | KIT | 不需装配，成套发货 | 有 | 标准 |
| 软件 | SW | 纯软件，无库存 | 无 | 无 |

**关键规则**：
- 采购件只有P/SI两种模板；自制件可为任一种。
- P与SI区别在于领料方式；AI与PH区别在于是否有库存。
- AOC只能在ATO模型下；POC只能在PTO模型下；PTO一般为产品第一级。
- 项目模板选择错误会导致计划逻辑错误（如SI设为P会造成大量假需求）。

### 阶段三：BOM清单管理
1. **清单类型**：
   - **标准清单**：构成固定（AI/PH/FG/SA）。
   - **模型清单**：可选（ATO模型/PTO模型）。
   - **可选类清单**：可选组件集合（AOC/POC）。
   - **计划清单**：描述计划百分比，代表产品族。
2. **父项-子项限制**：PTO可含PTO/ATO/POC/AI/PH/P/SI/KIT；ATO可含ATO/AOC/PH/AI/P/SI；FG可含AI/PH/P/SI等。
3. **共享与拷贝**：相同类型项目可共享清单；类似清单可拷贝后修改；不能创建参照链。
4. **版本控制**：按项目版本生效日期控制；新版本生效后老版本不可修改但可查询/生产；制成板与PCB版本一一对应。
5. **供应类型**：推式（任务令发料）、装配拉式（完工入库冲减）、操作拉式（工序完工冲减）、大量（杂项发料）、虚拟（自动分解子项）、供应商（外加工）。

### 阶段四：ECO工程更改控制
1. **定义**：Engineering Change Order，用于定义和修改清单，保证修改可追溯。
2. **流程**：
   - **定义**：项目人员在MRPII工程环境定义ECO，记录申请人、部门、更改原因、内容。
   - **审批**：提交BOM清单归档申请表，经审核批准后由BOM数据管理部实施。
   - **实施**：手工实施或设状态为"计划"按生效日期自动实施；实施后不可修改。
3. **状态管理**：打开→暂挂→计划→实施→取消。
4. **计划ECO**：用于转试产/转产，生效日期设为另一项目耗尽日期，关键器件库存耗尽后再切换，减少呆死料。
5. **注意事项**：
   - 项目组不要将ECO状态定为"计划"以免系统自动实施后无法修改。
   - 新版本一旦生效不能删除。
   - 多份清单同时更改可放在同一ECO中。

### 阶段五：计划百分比维护
1. **定义**：组件计划量 = 装配件计划订单数量 × 组件用量 × 组件计划百分比。
2. **维护依据**：
   - 历史要货配置统计（从MRPII系统提取）。
   - 未来配置情况预测（市场计划提供）。
   - 相关产品配置方案（研发提供）。
   - 版本切换信息（计划员掌握）。
3. **调整流程**：计划员组织 → 研发、市场、二级计委共同参与 → 二级计委文件下发执行。
4. **注意事项**：
   - 仅模型/可选类/计划清单的组件可设≠100%的百分比。
   - 用量小且月度波动大的项目考虑单列，不用百分比。
   - 新产品无发货记录，建议多用单列计划。
   - 单列计划项目百分比为0，不列入调整报表。
   - ECO项目的计划百分比在排产前重点关注。

## Key Principles
- BOM的正确性直接影响商务、计划、采购、成本的准确与可信度。
- 项目模板选择决定计划逻辑和库存行为，必须严格按业务场景选择。
- ECO管理的核心是"可追溯"和"可控"，计划ECO是减少呆死料的关键手段。
- 计划百分比是计划工作的"基础中的基础"，多方参与调整才能保证准确。
- 制成板与成品板版本一一对应，版本混乱会导致计划量失真。

## Failure Modes
| 症状 | 可能原因 | 对策 |
|------|----------|------|
| 计划结果漏掉某物料 | 项目模板选择错误（如应PH设为AI）/ 预测控制属性错误 / 父子项同时MPS | 检查模板和预测控制；避免不可选父子项同时MPS |
| ECO实施后大量呆料 | 未评估库存影响/生效日期过早/未用计划ECO耗尽库存 | 实施前评估库存+在途；对转产用计划ECO按耗尽日期生效 |
| 计划百分比持续偏差 | 只由计划员单方面调整/未参考历史统计/未考虑版本切换 | 建立多方参与机制；每月提取历史配置；版本切换时同步调整 |
| 虚拟项目产生库存 | PH模板误设为AI / 供应类型未设为虚拟 | 检查模板和供应类型；虚拟件提前期设为0 |
